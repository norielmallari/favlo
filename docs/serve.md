# Serve

As-built listener and daemon. The map and the write set are [../ARCHITECTURE.md](../ARCHITECTURE.md). That file wins for which files an agent may edit. Assisted features are [ai-assistance/README.md](ai-assistance/README.md).

`favlo serve` on a terminal is the operator console. `favlo serve --non-interactive` starts the daemon and exits. The daemon listens on `127.0.0.1:8129` with nothing loaded. It does not read the terminal. Closing the terminal leaves the daemon running. A later `favlo serve` attaches to the daemon already listening on that address. The console prints `listening on http://127.0.0.1:8129`, then paints telemetry as it arrives. The prompt is a bare line. `quit` stops the daemon. `/quit` is the same command. The daemon closes every open pipeline. A daemon that stays up is killed. Ctrl+C closes every open pipeline and exits the console. The daemon keeps listening. `reload` closes every open pipeline, drops every waiter in the foreground queue and the media queue, drops a media task that has not started, drops the imported pipeline modules, and stays attached. `/reload` is the same command. A waiter does not run. The request that holds the GPU is cancelled. The next request loads those modules again. A line that is not one of those commands is ignored. The console does not call a model. `POST /mcp` answers with no pipeline loaded.

`--max-memory` is passed to a pipeline whose `open_runtime` accepts it, as the maximum bytes that runtime may allocate. `owner` is passed the same way. The listener sweeps the owners recorded for that opening after `close`, and sweeps spans created during an `open_runtime` that raises. A pipeline that does not accept `owner` keeps the owner string it already mints.

A pipeline writes a reply and does not see a socket. `json` is the HTTP body, encoded before that call returns. A video or music job then keeps updating the stored job. A stream is `begin_events`, then `event`, then `done`. `stopped` is true when the client has gone. A chat still waiting then leaves the queue and does not run. A chat already on the GPU checks that and ends the forward.

A pipeline smoke can run while this daemon is up. `python -m favlo.smoke_lock acquire` closes the resident model when no request is open, and chat then returns 503 until `python -m favlo.smoke_lock release`. A request that is already open is left running. The daemon process is not stopped. After release, the next chat loads a model again.

`GET /v1/models` lists a registered row when its pipeline defines `handle_chat` and does not define `handle_image`, `handle_video`, `handle_music`, `handle_voice`, or `handle_embed`. Each object includes `context_length`. Media rows are the media MCP tools. A pipeline file that cannot be loaded is omitted. `GET /v1/models/{id}` for an omitted id is 404. `POST /v1/embeddings` takes `model` and `input` as one string or an array of strings and returns one dense vector per input. The daemon admits the GPU from a foreground queue and a media queue. Embeddings sit ahead of chats that have not started. An embeddings request waits until the open chat completion returns. A chat that has not started waits while an embeddings request is queued or running. A chat that arrives while media holds the GPU leaves `preempt` set until the chat queue is empty. An embeddings request does not set `preempt` and does not close the resident model. Its process closes when the request returns. The default context length is 131072. A completion's final `usage` object includes `prompt_tokens`, `completion_tokens`, `total_tokens`, `context_length`, and `prompt_tokens_details.cached_tokens`. `POST /v1/pipelines/close` closes every open pipeline and does not stop the daemon. `POST /v1/pipelines/reload` does that, drops every waiter in the foreground queue and the media queue, drops a media task that has not started, and drops the imported pipeline modules. A waiter does not run. The request that holds the GPU is cancelled. `POST /v1/chat/completions` loads the pipeline that row names. A path under `/v1/images`, `/v1/videos`, or `/v1/audio` is 404. Media is `POST /mcp`. One chat completion runs at a time. A completion that arrives while another is open waits until that one has returned, and the daemon logs `waiting for the open request`, which the terminal prints. `GET /v1/models` answers while a completion is open. A connection that keeps its socket open between requests does not hold the completion slot. A connection that sends no request is dropped after 10 seconds. A different folder or a different pipeline unloads the previous record first and waits until that process's pages are reclaimable. A reclaimable count that stops rising ends that wait. An unknown language id is 404.

A served chat handler is a `LanguagePipeline`. A served embeddings handler is an `EmbeddingsPipeline`. A served image, video, music, or voice handler is a `MediaPipeline`. The daemon still admits the GPU. `POST /mcp` is the media MCP endpoint; the tool and resource catalog is [MCP.md](../MCP.md). Protocol `2026-07-28`, Streamable HTTP, one JSON object per POST, no session, and no GET event stream. `server/discover` returns `supportedVersions`, including `2026-07-28`, and capabilities that include `io.modelcontextprotocol/tasks`. `initialize` for any handshake other than that version returns JSON-RPC `-32022`. A client then discovers. Every request repeats the version and the client capabilities in `params._meta`, and sends headers `mcp-protocol-version` and `mcp-method`. `tools/call` and `resources/read` also send `mcp-name`. The media tools are `list_image_models`, `list_video_models_i2v`, `list_video_models_t2v`, `list_music_models`, `list_voice_models`, `media_status`, `media_cancel`, `generate_image`, `generate_video_i2v`, `generate_video_t2v`, `generate_music`, and `generate_voice`. A row from `list_voice_models` includes `voices` when that pipeline defines `list_voices`. `generate_voice` selects one of those ids with `voice`. An empty `voice` uses the zero speaker. A row includes `emotions` when that pipeline defines `list_emotions`. A square-bracket tag in `input` uses one of those ids. A generate tool runs as a task when the client advertises `io.modelcontextprotocol/tasks`. That call returns immediately with `status` `working`, `pollIntervalMs` 2000, and `resultType` `task`. The job is queued in the daemon. One job runs at a time, in a pipeline process. The daemon keeps the queue, the task record, and the memory ledger. A pipeline crash fails that job. The daemon waits until the pages that process wired are reclaimable. A reclaimable count that stops rising ends that wait. It drops the owners it reported, and the next job starts another process. The call does not start the GPU. A client that does not advertise the extension receives the finished tool result on the same `tools/call`. One worker runs those tasks in order. `list_image_models`, `list_video_models_i2v`, `list_video_models_t2v`, `list_music_models`, `list_voice_models`, `media_status`, and `media_cancel` run immediately and do not enter that queue. `media_cancel` and `tasks/cancel` discard the same task and its stored file. A chat that arrives while media holds the GPU leaves `state["preempt"]` set until the chat queue is empty. The media call checkpoints at its next stage boundary and closes the device. The listener drops that runtime before the chat model allocates, and calls the same handler again from the checkpoint only after the foreground queue has drained. An embeddings request does not set `preempt` and does not close the resident model. It opens its own process for that request and closes it when the request returns. Embeddings still run ahead of chats that have not started. Until a pipeline reads that event, the handler runs to completion. `tasks/get` and `media_status` report `status` `working` and `statusMessage` `task is ongoing` for a task that is still queued and for a task paused while the foreground queue runs. A queued task also reports `position`. A paused task also reports `stage` `paused` and keeps that clip's progress. `state["cancel"]` is a separate event, set only for the task that is running. A queued cancel never starts that task. Image `n` from 1 to 10 is one task. A completed image or music result inlines the file only when the client asked and the decoded bytes are at most 1 MiB. A video result is a `resource_link` `favlo://videos/{id}.mp4` of type `video/mp4` and is never inlined. An image link is `favlo://images/{id}.png`. A music or voice link is `favlo://music/{id}.{ext}` or `favlo://voice/{id}.{ext}`, where `{ext}` is `mp3`, `wav`, or `flac` for the job's response format. `resources/read` of that URI returns those bytes, and the content URI is the same string, so a download named from the URI keeps the extension. A music or voice URI with no suffix returns the job's format while that job is in memory, and the WAV otherwise. It does not encode a different format for a URI with no suffix. `generate_video_i2v` `image` is an id starting with `image_` from `generate_image`, or a PNG block `{"type": "image", "data": "<base64>"}`. A filesystem path and a `favlo://` URI are refused. `generate_video_i2v` and `generate_video_t2v` take optional `duration` in seconds. An omitted `duration` uses the model default. `size` is required. `list_video_models_i2v` and `list_video_models_t2v` include `resolutions` when that pipeline defines `list_resolutions` and `video_modes` names that mode. A pipeline that names both modes is on both lists. Each entry has `name`, `orientation`, and `size`. `generate_video_t2v` takes no still. `quality` is `auto`, `low`, `medium`, `high`, `xhigh`, `max`, `standard`, or `hd`. There is no later re-encode method on MCP. A path under `/v1/images`, `/v1/videos`, or `/v1/audio` is 404. The stored file stays on disk, and `resources/read` reads it. An MCP client, including Hermes, adds:

```yaml
mcp_servers:
  favlo:
    url: "http://127.0.0.1:8129/mcp"
```

Cursor in this repo reads `.cursor/mcp.json`. That entry is type `http` and the same URL. It is not a stdio command.

The daemon writes one JSON event per line to `~/.favlo/logs/serve-<port>.log`. Durable lines are also appended to `~/.favlo/logs/favlo.log`. The live progress row is not written there. `~/.favlo/settings.json` key `log_max_bytes` is the most bytes `favlo.log` may hold. The default is 1048576. Key `video_ttl_seconds` is how long a stored MP4 stays. Key `image_ttl_seconds` is how long a stored PNG and its RGB file stay. Key `music_ttl_seconds` is how long a stored WAV and its encoded siblings stay. Key `voice_ttl_seconds` is how long a stored spoken WAV and its encoded siblings stay. Each default is 86400. An omitted or unreadable value uses that default. A sweep when the listener starts, and again after each clip or image is stored, deletes a pair that has reached that age. A stored clip's sweep also drops its job. Keys `max_tokens` and `thinking_budget` apply only when present. An omitted `max_tokens` on the request and in that file does not cap the completion. An omitted `thinking_budget` does not close a think block on a token count. The first serve creates that file when it is missing. A line that would pass the cap leaves the newest bytes that still fit, starting at the next line when one fits.

A terminal `favlo serve` whose registry has no rows checks that a small shader compiles at Metal 4.1, then runs `favlo --qwen36-35b-a3b setup` before the daemon starts. The checkpoint and the packed directory are [guides/models.md](guides/models.md). `--non-interactive` does not download. A pipe does not download. A failed check or a failed download exits. The next `serve` on a terminal continues from the files already written.

A pipeline heartbeat runs in the daemon after the request closes. The terminal does not start an agent on a timer.
