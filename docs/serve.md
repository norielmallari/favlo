# Serve

As-built listener and daemon. The map and the write set are [../ARCHITECTURE.md](../ARCHITECTURE.md). That file wins for which files an agent may edit. Terminal chat is [ai-assistance/README.md](ai-assistance/README.md).

`favlo serve` on a terminal is the CLI. `favlo serve --non-interactive` starts the daemon and exits. The daemon listens on `127.0.0.1:8129` with nothing loaded. It does not read the terminal. Closing the terminal leaves the daemon running. A later `favlo serve` attaches to the daemon already listening on that address. `/quit` stops the daemon. Ctrl+C stops the daemon when this terminal started it.

`--max-memory` is passed to a pipeline whose `open_runtime` accepts it, as the maximum bytes that runtime may allocate. `owner` is passed the same way. The listener sweeps the owners recorded for that opening after `close`, and sweeps spans created during an `open_runtime` that raises. A pipeline that does not accept `owner` keeps the owner string it already mints.

A pipeline writes a reply and does not see a socket. `json` is the HTTP body, encoded before that call returns. A video or music job then keeps updating the stored job. A stream is `begin_events`, then `event`, then `done`. `stopped` is true when the client has gone. A chat completion checks that and ends the forward.

A pipeline smoke can run while this daemon is up. `python -m favlo.smoke_lock acquire` closes the resident model when no request is open, and chat then returns 503 until `python -m favlo.smoke_lock release`. A request that is already open is left running. The daemon process is not stopped. After release, the next chat loads a model again.

`GET /v1/models` lists registered language rows and includes `context_length` on each object. A row whose pipeline defines `handle_image`, `handle_video`, `handle_music`, `handle_voice`, or `handle_embed` is omitted. `GET /v1/models/{id}` for that id is 404. `POST /v1/embeddings` takes `model` and one string `input` and returns one dense vector. An embeddings request waits until the open chat completion returns and does not set `preempt`. A chat that has not started waits while an embeddings request is queued or running. The default context length is 131072. A completion's final `usage` object includes `prompt_tokens`, `completion_tokens`, `total_tokens`, `context_length`, and `prompt_tokens_details.cached_tokens`. `POST /v1/chat/completions` loads the pipeline that row names. A path under `/v1/images`, `/v1/videos`, or `/v1/audio` is 404. Media is `POST /mcp`. One chat completion runs at a time. A completion that arrives while another is open waits until that one has returned, and the daemon logs `waiting for the open request`, which the terminal prints. `GET /v1/models` answers while a completion is open. A connection that keeps its socket open between requests does not hold the completion slot. A connection that sends no request is dropped after 10 seconds. A different folder or a different pipeline unloads the previous record first. An unknown language id is 404.

`POST /mcp` is the media MCP endpoint, protocol `2026-07-28`, Streamable HTTP, one JSON object per POST, no session, and no GET event stream. `server/discover` returns `supportedVersions`, including `2026-07-28`, and capabilities that include `io.modelcontextprotocol/tasks`. `initialize` is not served. Every request repeats the version and the client capabilities in `params._meta`, and sends headers `mcp-protocol-version` and `mcp-method`. `tools/call` and `resources/read` also send `mcp-name`. The seven tools are `list_media_models`, `media_status`, `media_cancel`, `generate_image`, `generate_video`, `generate_music`, and `generate_voice`. A row from `list_media_models` includes `voices` when that pipeline defines `list_voices`. `generate_voice` selects one of those ids with `voice`. An empty `voice` uses the zero speaker. A generate tool runs as a task when the client advertises `io.modelcontextprotocol/tasks`. That call returns `status` `working`, `pollIntervalMs` 2000, and `resultType` `task`, and does not start the GPU until the worker reaches it. A client that does not advertise the extension receives the finished tool result on the same `tools/call`. One worker runs those tasks in order. `list_media_models`, `media_status`, and `media_cancel` run immediately and do not enter that queue. `media_cancel` and `tasks/cancel` discard the same task and its stored file. A chat completion that arrives while media holds the GPU sets `state["preempt"]`, a `threading.Event`. The media call checkpoints at its next stage boundary and closes the device. The listener drops that runtime before the chat's model allocates. The waiting chats run, and the listener calls the same handler again from the checkpoint. Until a pipeline reads that event, the handler runs to completion. `tasks/get` and `media_status` report `stage` `paused` and `status` `working` while those chats run. `state["cancel"]` is a separate event, set only for the task that is running. A queued cancel never starts that task. Image `n` from 1 to 10 is one task. A completed image or music result inlines the file only when the client asked and the decoded bytes are at most 1 MiB. A video result is a `resource_link` `favlo://videos/{id}.mp4` of type `video/mp4` and is never inlined. `resources/read` of `favlo://images/{id}` or `favlo://videos/{id}.mp4` returns the stored file. `resources/read` of `favlo://music/{id}` returns that clip in the job's response format and does not encode a different one. The still on `generate_video` is a stored image id or a PNG image block. A filesystem path is refused. `quality` is chosen on `generate_video`. There is no later re-encode method on MCP. A path under `/v1/images`, `/v1/videos`, or `/v1/audio` is 404. The stored file stays on disk, and `resources/read` reads it. An MCP client, including Hermes, adds:

```yaml
mcp_servers:
  favlo:
    url: "http://127.0.0.1:8129/mcp"
```

Cursor in this repo reads `.cursor/mcp.json`. That entry is type `http` and the same URL. It is not a stdio command.

The daemon writes one JSON event per line to `~/.favlo/logs/serve-<port>.log`. Durable lines are also appended to `~/.favlo/logs/favlo.log`. The live progress row is not written there. `~/.favlo/settings.json` key `log_max_bytes` is the most bytes `favlo.log` may hold. The default is 1048576. Key `video_ttl_seconds` is how long a stored MP4 stays. Key `image_ttl_seconds` is how long a stored PNG and its RGB file stay. Key `music_ttl_seconds` is how long a stored WAV and its encoded siblings stay. Key `voice_ttl_seconds` is how long a stored spoken WAV and its encoded siblings stay. Each default is 86400. An omitted or unreadable value uses that default. A sweep when the listener starts, and again after each clip or image is stored, deletes a pair that has reached that age. A stored clip's sweep also drops its job. Keys `max_tokens` and `thinking_budget` apply only when present. An omitted `max_tokens` on the request and in that file does not cap the completion. An omitted `thinking_budget` does not close a think block on a token count. The first serve creates that file when it is missing. A line that would pass the cap leaves the newest bytes that still fit, starting at the next line when one fits.

A terminal `favlo serve` whose registry has no rows checks that a small shader compiles at Metal 4.1, then runs `favlo --qwen36-35b-a3b setup` before the daemon starts. The checkpoint and the packed directory are [guides/models.md](guides/models.md). `--non-interactive` does not download. A pipe does not download. A failed check or a failed download exits. The next `serve` on a terminal continues from the files already written.

A pipeline heartbeat runs in the daemon after the request closes. The terminal's only heartbeat is the agent check in [ai-assistance/README.md](ai-assistance/README.md).
