# Inkling 2 Mini

The language pipeline loads one folder, `Inkling-2-Mini-fp4-gptq-foem`. `setup` copies the checkpoint into that folder and writes a raw record. `resident.bin` holds the float16 and float32 language planes, including the float16 attention and output-projection planes. A record sealed earlier keeps nearest E4M3 for those two planes. `experts.bin` holds the Metal fp4 experts for layers 0–19 and the MXFP8 experts for layers 20–23. `vision.bin` and `mtp.bin` are separate files. `manifest.json` indexes every tensor. The language open preads `resident.bin` and `experts.bin` in 8 MiB pieces and does not open a safetensors weight file. The fused attention plane and the output projection are float16. Prefill multiplies them with `matmul2d`. One token uses the half GEMV. A record that still stores those planes as nearest E4M3 uses the fp8 GEMV for one token. The head and the embedding stay float16. The router, the sink, the dynamic convolution taps, and the message gates stay half. Layers 0–19 store NVFP4 experts. `calibrate` dequants those experts and rounds them to Metal fp4 with GPTQ-FOEM, using the Hessian of each expert's own inputs, then seals that payload into `experts.bin`. `bake` writes a nearest pack when the expert file is missing, and the same seal copies it.

`runtime` may still say `metal41`. `serve` imports `inkling_2_mini.portable`. A row that says `metal41` loads that entry. `metal41` re-exports the pipeline. The device opens from `portable` `open_runtime`. On a machine that is not Apple Silicon with Metal 4.1, that open refuses with `this runtime cannot run here`.

## Setup

`setup` lists the repository on `huggingface.co`, checks that the volume can hold the bytes still missing, and downloads the served files into `Inkling-2-Mini-fp4-gptq-foem`. That folder is the registry id. A file that is already the published length is kept. A published checksum is checked once and recorded in `fetch_complete.json`, so the next run does not read the weight file again. The language shard is then rewritten: bf16 tensors become float16, and `model.visual` tensors move to `vision.safetensors`. `repack.json` records that rewrite so the next setup does not replace the float16 shard with the hub file. `mtp.safetensors` is downloaded beside it. When the expert pack, the dense pack, and the vision pack match `config.json`, setup copies them into `resident.bin`, `experts.bin`, and `vision.bin`, writes the drafter as float16 to `mtp.bin`, and writes `manifest.json`. It then removes the safetensors weight files. The next setup does not download those files again. `calibrate` reads the language shard, so another calibration downloads the checkpoint again and runs before the folder is sealed.

The registry row then stores `kv_cache` `half`, context 131072, `enable_thinking` true, `reasoning_effort` `high`, and `preserve_thinking` true. `thinking` and `instruct` store one sampler: temperature 1.0, top-p 1.0, top-k 0, and presence penalty 0. A request sets the effort with `reasoning_effort`. The template maps `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max`.

A replaced weight file drops the record and the packs first. `setup` writes the expert pack when it is missing or does not match `config.json`, then seals the record. The head stays float16 in `resident.bin`.

## Dense planes

`model.llm.layers.{i}.attn.wq_du`, `wr_du`, `gate_attn`, `wk_dv`, and `wv_dv` stay float16 in `resident.bin`, and the open fuses them in that order. `attn.wo_ud` stays float16. The prefix-store tag for that record is `fp16`. A record sealed with nearest E4M3 still stores `layers.{i}.attn` and `layers.{i}.wo` as one E4M3 plane each, one E8M0 scale per 32 along K, and its tag stays `fp8-nearest`. `unembed` is the head, pread as float16 and padded to the kernel row count. The expert planes stay on the baked pack.

## Schedule

24 stored layers, 48 visits. Layers 0–5 run once. Layers 6–17 run three times, and every pass starts from the embedding plus the prelude block. Layers 18–23 run once. Six layers make one block. Inside a block, each attention output and each expert output goes through the residual short convolution and is added to that block's partial sum. The next block stores the partial as a finished summary and starts again at zero. The embedding is the first summary.

A sublayer does not read the partial directly. It mixes the finished summaries and the current partial: keys are RMS-normalized, the learned query is scaled by `1/sqrt(2304)`, and the values are the normalized sources. Checkpoint `attn_queries.{i}` feeds layer `i + 1`. Layer 0 has no attention query and reads the embedding. The three-query tensors land on the full-attention layers, so their query, key, and value streams are separate mixes. MLP queries stay on the layer they are stored with. The output query mixes the finished summaries for the final RMSNorm.

A later core pass reads the previous pass through four messages per layer. For core index `i`, the query message is row `2i` and the MLP message is row `2i+1` of `middle_cycle_cross_pass_queries`. The key message is row `2i` and the value message is row `2i+1` of `middle_cycle_cross_pass_kv_queries`. The message gate is the published rank-64 blend

```text
h = W_down · [rms(input), rms(message)]
out = (1 − tanh(W_forget · h)) · input + tanh(W_gain · h) · message
```

The blend is applied to the mix, before the sublayer RMSNorm. Full-attention layers are 5, 11, 17, and 23. The other twenty layers use a sliding window of 1024. Each visit has its own key, value, and convolution state.

## Attention

24 query heads, 8 key/value heads, head dim 128. There is no rotary embedding on the text stack. A relative table of extent 1024 adds a per-head bias for distances below that extent. Query, key, and relative vectors are L2-clipped at the thresholds in `config.json`. The query and the relative vector use their learned per-channel scales. The key scale is one. An input-dependent sink logit is an extra attention slot with no value. The output is gated before the output projection, and that projection then passes through the residual short convolution

```text
y[t] = (x[t] + sum_lag w[W-1-lag] x[t-lag]) / sqrt(W+1)
```

with `W = 4`. The last stored tap multiplies the current step. Values are RMS-normalized per head with no gamma. Local layers share one attention RMSNorm. Full layers use separate query, key, and value norms. Their key and value convolutions add the current token and a per-token tap to the static tap, then divide by `sqrt(2W+1)`.

Keys and values are stored half, 1024 channels per position. A full-attention visit keeps one plane for the served context. A local visit keeps a ring of 1024 and reads only that window. Prefill copies the ring into one contiguous span so `attend_flash` can multiply it, then writes the last 1024 keys back. Decode stores and reads the ring in place.

Prefill attention is `attend_flash`. One threadgroup of four simdgroups owns 32 query rows of one head. It walks 64-key tiles. `matmul2d` multiplies the half query tile by the key tile, and a second `matmul2d` multiplies the half probabilities by the value tile. Each lane then adds the relative bias for its scores, applies the window and the causal mask, and updates the running maximum and sum. The sink logit seeds that maximum and sum, and the sigmoid gate multiplies the output per channel.

Decode attention is `attend_group`. One threadgroup of eight simdgroups owns one key/value head and its three query heads. The keys split into spans of at least 256, at most four spans per head. Inside a span, eight lanes share one key: each holds sixteen channels of the three queries, and a shuffle reduction finishes the dot. The relative bias is skipped past distance 1024. Each simdgroup keeps an online softmax. The threadgroup merges its eight partials in threadgroup memory and writes one partial per query head. The last span to finish, counted with an atomic, merges the spans, adds the sink, and applies the gate.

## Experts

Eight of 128 experts, no shared expert. `calibrate` writes `experts.bin`: layers 0–19 are Metal fp4 from GPTQ-FOEM on the dequantized NVFP4 weights, and layers 20–23 are the MXFP8 bytes as stored. The Gram for an up projection is the packed half rows routed to that expert. The Gram for a down projection is that expert's gated half rows. Both products are one `matmul2d` grid per wave of experts, encoded in the forward command buffer. The transpose walks the rows routed to each expert. Rounding keeps a wave of experts on one grid while the host factors the next wave and checks the output error. One prefill updates every resident NVFP4 layer. A layer Gram is about 3.3 GB. One layer is the floor. The expert wave is how many of the 128 products fit beside that Gram, and a full wave is reserved before a second layer is added. `bake` writes the same file with a nearest NVFP4 remap when the pack is missing. The open reads `experts.bin` in 8 MiB pieces after the dense planes. A missing `experts.bin` leaves the record incomplete, and the open refuses it. Before the record is sealed, a missing pack still reads the checkpoint and requantizes layers 0–19 on the device. When the budget holds every image, the atlas is complete and each tensor is read once. Otherwise it keeps eight images, the experts one token routes, and copies a miss in before that expert runs.

One layer records its attention kernels into one command buffer and waits when the CPU reads the router. A complete atlas then records that layer's expert kernels into the next buffer. A single token records the whole forward in one command buffer. Its fp4 projections are a four-row GEMV, and its RMSNorm and block mix each run as one threadgroup of 256. `route_gemv` scores the router in 32 threadgroups of four rows. The last group to finish, counted with an atomic, picks the eight experts on the GPU, and those experts run as one grid of four-row groups. A decode step reads its token from the device, so the host encodes step n + 1 while the device runs step n. When sampling allows it (no top-k, top-p, penalty, or forbidden token), the GPU draws the token with a Gumbel maximum. Prefill still waits at the router so the CPU can group tokens. A partial atlas waits after each expert, because the next expert reuses the same slot. The router scores with a sigmoid. The gate bias is added only to choose the eight experts. The selected sigmoid scores are renormalized and multiplied by `route_scale` 8. The fused gate and up rows are interleaved, even row then odd row. The activation is `softcap(gate) * sigmoid(gate) * softcap(up)`, with caps 4 and 25. The expert output then takes the same residual short convolution as attention.

NVFP4 reconstruction is `e2m1 * e4m3(block_scale) * (amax / 2688)`. The 2688 is the file's outer-scale denominator, which is `448 * 6`. The load kernel turns each block of 32 into an E2M1 code and one E8M0 scale. K is padded to a multiple of 256, so the down projection's 1152 becomes 1280 and the extra columns stay zero. MXFP8 weights are E4M3 with one E8M0 scale per 32 along K, which is the native scale plane `{32, 1}`.

## BF16 quantize

`quantize` reads a BF16 checkpoint with the same expert tensor names and writes a second sealed folder. The source folder is read in place. A sharded index is read from each named file. A folder with no index is every safetensors file in that folder. Those files stay in the source folder. A layer's expert projections are one sequential read in 8 MiB pieces, and a gap shorter than 8 MiB stays in that read. Projections in different files are separate reads. Scoring and packing use that buffer. The registry source is that folder and the directory is the sealed folder. A template that lists reason modes samples at temperature 1, top-p 0.95, top-k 64, and presence penalty 0, with thinking at high and instruct at minimal. Any other template keeps the package sampler. It does not change `Inkling-2-Mini-fp4-gptq-foem`. `--expert-fp8` is the percentage of the 3072 routed experts stored as MXFP8. The count is `floor(percent * 3072 / 100)`. The score is the larger relative RMS of an fp4 restoration of that expert's gate-up and its down matrix, on the real columns only. Ties keep the lower index. The scores are cached in `expert_error.json`. `--promote firing` ranks `firing.sqlite` instead and writes `expert_firing.json`. Each expert image is data, 128-byte aligned, then its E8M0 scale, 128-byte aligned. fp4 K is padded to a multiple of 256. The pack is `experts-fp4.safetensors` with a `widths` tensor, one blob per projection, and per-expert data and scale offsets. `seal` copies that payload into `experts.bin`. `experts/widths.bin` is the same width plane, one byte per expert. Attention and the output projection stay float16. The embedding and the head stay float16. A layer whose experts are one width dispatches that width once. A mixed decode step runs one gate and one down. Each of the eight slots reads that expert's width, and the down applies the residual convolution. A mixed prefill runs the fp4 and fp8 tiles with a width skip.

## Expert firing

A finished request writes `~/.favlo/telemetry/<folder>/firing.sqlite`. The device counts the real expert ids, eight per token, on the stored layer of each visit. Layers 6–17 therefore receive three visits, and a full token is 384 hits. Prefill and decode tokens are counted once, from the uncached suffix and the produced steps. A cancel drops the decode counts. The lull after close pulls the hist plane and inserts the row. A request that is still running is not in the log.

## Chat

The checkpoint template injects `Thinking effort level:` and, when tools are present, a `tool_declare` block. A listed effort name is passed through. A number is clamped to `[0.0, 0.99]`. A template that lists mode names receives the name, and a name outside that list uses `off` at level zero and `low` otherwise. The template has no generation prompt: the model writes `<|message_model|>` itself, then one body marker. The stop token is `<|content_model_end_sampling|>` (200006). Logits past the unpadded vocab of 200058 are ignored. Thinking text is `<|content_thinking|>`. Reply text is `<|content_text|>`. A tool call is `<|message_model|>name<|content_invoke_tool_json|>` and a JSON object with `name` and `args`. `tool_choice` `none` does not sample that invoke token. Each message ends with `<|end_message|>`.

The parser splits the completion at those markers. A body cut off by the length limit keeps its text. A tool body is read with a JSON decoder that tolerates raw control characters. A backslash that does not start a JSON escape is doubled and the body is read again. Text with no markers is the reply.

A required tool forces the opening `<|message_model|>name<|content_invoke_tool_json|>{"name":"…","args":`. With thinking off and no tool to call, the opening is `<|message_model|><|content_text|>`. Otherwise the model opens its own message. `encode_chat` appends the forced text to the prompt tokens, so a prompt length counts it. The parser treats it as part of the completion.

A stream decodes tokens incrementally and holds back a split UTF-8 tail for at most eight tokens. A gate over the markers emits reasoning deltas, reply deltas, and, for a call, an added item and argument deltas as the JSON arrives. A writer thread sends the events from a queue. A hosted `web_search` request adds its search item first, in the stream and in the stored output.

A Gumbel draw takes 23 bits of a hash, adds one half, and scales by `2^-23`, so the uniform is exact in float and never 0 or 1.

## Prefix store

The pipeline uses the shared SSD prefix store. A record has one `conv` region with every short-convolution state of the 48 visits, then `kNN` and `vNN` for each visit. A full-attention visit stores positions `0 .. count-1`. A local visit stores only the last 1024 of them. A record continues a prompt only when the prompt is longer, so an exact-length file is never sampled and the next prefill steps at least one token.

During prefill, the device state at each `<|message_user|>` after the first is written when another token still follows that marker. The first marker is the chat template. Ending the piece there runs a second forward, and the stored prefix is one every later one-turn prompt shares. A file that is only that template is not reloaded. A later marker is a resume point: a prompt that rewrites that user text loads the boundary and prefills from there. The live sequence is also written after prefill and after decode. The device must then hold exactly the prompt and every returned token. Pipelined decode may already have applied the stop token. Each step therefore first copies the convolution states into one of two snapshot slots, and the step that applied the stop token is taken back from its slot. Keys past the returned tokens are never read. A decode that ended at its limit runs one more step to apply its last token. With `favlo:fill_decode` no snapshot is taken.

## Vision

A still is padded on the right and bottom to a multiple of 40 pixels. The pad value is -1 on the 0–255 scale, then rescaled and normalized with mean 0.5 and standard deviation 0.5. One language token is one 40 by 40 tile, and the tile is four 20 by 20 patches. The patch embedding, the 32 by 32 position table, each attention and MLP linear, and the two projector linears are E4M3 with one float32 scale per 32 along K. Layer norms, layer scales, and biases stay half. `bake` writes the fp8 vision pack when it is missing or does not match `config.json`. Setup copies that pack to `vision.bin`.

A copied `<|unused_200054|>` in message text, a tool argument, or a tool result stays text. The template emits that sentinel only for an image part. An image request reads `vision.bin` straight into one device buffer, in 8 MiB pieces. The tower is 23 pre-norm layers with axial RoPE, then the projector. The language embedding is RMSNormed first. The merged rows then replace the image-token positions, so those rows keep the projector scale. The pack is released before prefill. The rows stay until that prefill finishes, then they are released. A repeat of the same bytes reads `~/.favlo/vision-cache/inkling_2_mini` and does not load the pack. An image already inside the prefix is not encoded again. The log lines are `vision patches`, `vision merged`, `vision cache`, and `vision cached`.

## Memory

The open reads `memory.budget()`. The fp8 attention plane, the output projection, and the head are pread from `resident.bin`. `experts.bin` is read in 8 MiB pieces. The language open does not map `vision.bin` or `mtp.bin`. An image request reads `vision.bin` and releases it. The half key/value cache reserves the served context for the eight full-attention visits and a 1024-token ring for each of the other forty. One staging span holds a local prefill chunk. Activation rows stay at 2048 when the complete atlas fits beside that cache. Otherwise the rows shrink, down to 256, and prefill walks the prompt in those rows, so the atlas can still hold every expert image. The atlas takes eight images only when a complete atlas does not fit at any of those widths. The window then steps down through 16384, 8192, 4096, 2048, 1024, and 512, only when those eight images and the cache do not fit. Below the minimum, open raises `MemoryError`. The key/value cache is half. The convolution states take one buffer and two snapshot slots, about 11.5 MB together.
