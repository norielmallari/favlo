# Favlo web

`favlo web` starts two children and waits. The API is FastAPI in `web-api/` on `127.0.0.1:8130`. The app is the Expo dev server in `web-spa/` on `127.0.0.1:8081`. Stopping the command stops both. A port that is already taken ends the command and names that port.

`favlo serve` stays on `127.0.0.1:8129`. This command does not start it. It does not start when the registry has no language model. The first run stores that registry model as the application default. The browser loads `http://127.0.0.1:8081` and calls the API. The API calls the listener for chat completions. It does not load a model.

Application state is SQLite at `~/.favlo/web/app.db`. The Favlo listener at `http://127.0.0.1:8129/v1` is a provider by default. When that provider is added, its models are read from the listener models endpoint. Refresh models reads that endpoint again. A new database includes an agent named Favlo. Its persona is the small horse, without the terminal opening line. The configuration tool group is enabled for that agent. The same group is enabled for the terminal. It is `read_guide`, `read_setup`, `run_setup`, `list_models`, and `download_suggestions`. Another agent leaves the group off until its details turn it on. Conversation tools are a second switch on those details, and they start off. The tools are `list_conversations`, `search_messages`, and `read_recent_messages`. While the switch is on, they read every agent session, channel, and workspace chat. A search returns a short snippet. A read returns the latest messages, oldest first, and the count is capped. Each agent's details choose a provider and a model. Until that choice is saved, the agent uses the application default. Configuration is a sidebar of sections. A catalog such as Agents lists entries in the second column and the selected entry in the third. A section that is not a catalog shows its fields in the second column. New entries are created from a button in the third column. Heartbeats lists agents in the second column, that agent's heartbeats in the third, and the selected heartbeat in the fourth. A heartbeat stores a five-field cron expression, a timezone, instructions, and whether it is enabled. The smallest interval is one minute. Run heartbeat starts that schedule in its own session. Heartbeat tools are a switch on the agent, and they start off. The tools are `list_heartbeats`, `add_heartbeat`, `update_heartbeat`, and `delete_heartbeat`. They store, change, and remove a schedule for that agent. Orchestration shows the server's quiet interval in minutes. The stored key is `heartbeat_seconds` in `~/.favlo/settings.json`, and the default is 5 minutes. MCP lists agents in the second column and that agent's servers in the third. The selected server is the detail: HTTP takes a URL, stdio takes a command, and Test connection lists the live tools in the form. The Favlo listener address and its `/v1` prefix are read at `/mcp`. Save stores the server and the tool-group switches. Favlo media tools are grouped as Image, Video, Music, Voice, Media tasks, and Memory. Each group has one switch. While a group is on, its tools are available on that agent's turns. A media tool that returns a task is polled with `tasks/get` at the server's interval. The finished result is written into the agent session that called the tool. Each agent has one Agent Channel and one long-lived channel session. A button shows a tint while it is pressed. A successful save shows one confirmation at the bottom of the screen. Dismiss closes it, and the rest of the screen stays usable. A chat message that contains a `favlo://` image, video, or audio link shows that stored file. Opening a conversation, or refreshing it, shows the latest message. A selected menu row keeps space around its focus ring so the outline stays visible.

Install the app dependencies once, start the listener, then start the web command:

```text
cd web-spa && npm install
uv run favlo serve --non-interactive
uv run favlo web
```

Open `http://127.0.0.1:8081`. A page opened at `http://localhost:8081` moves to that address before it calls the API.
