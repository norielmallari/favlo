# Qwen3.6-35B-A3B

As-built note for the `qwen36-35b-a3b` pipeline. Download, pack, and the first chat are [SETUP.md](SETUP.md). The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

`handle_chat` is a `LanguagePipeline`. The completion, the sampler, and the stream stay in this package. Clients reach this pipeline through `favlo serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `kernels`, `quantize`, `mtp-fp8`, `bf16`, `complete`, and `models` require `favlo --qwen36-35b-a3b`. That flag loads `pipelines/metal41/qwen36-35b-a3b.py`, which loads `qwen36_35b_a3b`. The package does not import `qwen38_flash_next` or `qwen38_27b`.

The official checkpoint is [Qwen/Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B). Those weights are under the Apache License, Version 2.0. Device spans come from the process memory manager. The atlas budget is that manager's reclaimable bytes plus the spans it still holds. `open_runtime` takes `owner` and every span from that opening uses it. `close` sweeps that string. A command that omits `owner` mints one from this runtime's id. The context still starts at 2048 tokens and grows until eight expert images no longer fit.

## Kernels

`kernels` compiles this package's shader library and fails if any kernel in that library does not produce a pipeline. It then dispatches the fp4 and fp8 `matmul2d` tiles, the int8 prefill tile, the fp4 GEMV, the 32-row projection, the float16 GEMV at 1 row and at 256 rows, one fp4 expert image of 1,671,168 bytes, the expert-slot remap, the vision `linear_fc1` pad (4320 by 1280, 16 rows dropped), the head-72 online softmax, the tanh GELU, one Gated DeltaNet step, and the 8192-channel convolution. The vision tower adds row LayerNorm, a padded fp4 activation cast, bias packing, erf GELU, and a batched head-72 attention. The host formulas for those dispatches live in `qwen36_35b_a3b/checks.py`. The fp8 decode dot loads both scale blocks of a 2048-wide row before the table lookup. One simdgroup owns one row.

The DeltaNet state is float32, 32 heads of `128×128`. The step decays the state by \(\alpha\), writes \(\beta(v - Sk)k^\top\), and reads with the query. Decode does that once per token. Prefill uses the same recurrence in chunks of 64 (Yang et al., Gated Delta Networks, §3.3), so the state update and the outputs run across the chunk and the 32 heads. The short convolution is one thread per token and channel. It reads the raw projection, including the three taps kept from the previous chunk, and writes the mixed values beside that projection. The output norm multiplies by the stored weight, then the output gate is SiLU. Query repeat is 2, the mixed vector is 8192 wide, and the gate is 4096 wide. Float16 vectors are cast to float in the shader that reads them. This form is what `kernels` checks. A BF16 layer step has not accepted it.

## Record

`quantize` streams a Hugging Face BF16 checkout into `models/<name>-fp8-e<P>`. `--expert-fp8` is the percentage of routed experts stored as fp8. Any number from 0 to 100 is accepted. The default is 20. 100 stores every routed expert as fp8. The count is the largest whole number that does not exceed that percentage, so 20% of 10,240 is 2,048. MTP weights are not packed. `mtp-fp8` adds them to a finished record. Each language expert's score is the max of the relative RMS of its gate-up and down planes, `||restored − weight|| / ||weight||`, on the fp4 restoration. The highest scores are promoted. An equal score keeps the lower index. Gate-up and down move together. The chosen rows and both plane scores are written to `expert_error.json` before the images are packed. With no `--src`, quantize reads `models/Qwen3.6-35B-A3B-bf16` and writes `models/Qwen3.6-35B-A3B-fp8-e20`. `favlo serve` on a terminal with an empty registry downloads [Qwen/Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) into that checkout with plain HTTP, packs the record, and removes the checkout unless `--keep-bf16` is set. `setup --repo` downloads another repository that uses the same tensor names. The value is `org/name` or a `huggingface.co` model link. `delete` removes one packed folder, its registry row, a checkout still under `models/`, and that record's prefix partition. With no `--name`, the packed folder is that repository's model name plus the quant format, and that folder is the registry id. `--expert-fp8` selects the format. The default is 20, which appends `-fp8-e20`. `--name` replaces the folder and is the registry id. The steps are [SETUP.md](SETUP.md). A pipe leaves the registry empty. `--src` names another checkout. `<name>` is the repository name when that source is a hub snapshot, and the directory name otherwise. A directory name that ends in `-bf16` drops that suffix. `--expert-fp8 0` writes `models/<name>-fp4` and leaves every quantized matrix at fp4.

An fp4 routed expert is one 1,671,168-byte image and an fp8 expert is one 3,244,032-byte image: gate-up `[1024, 2048]` then down `[2048, 512]`, with an E8M0 scale every 32 along K. File order is the router order. The 256 images of one plane are packed together, up to 8 at a time. `experts/widths.bin` is 40 × 256 bytes of 4 or 8, and `experts/offsets.bin` is the byte offset of each image. MTP uses `experts/mtp.widths` and `experts/mtp.offsets`. The router matrix stays in checkpoint order. `remap_expert_ids` runs only when `experts/order.bin` is present. Language experts are `experts/<layer>.bin`. MTP routed experts are `experts/mtp.bin`. `mtp-fp8` reads a local checkout and stores every MTP routed expert and the dense MTP matrices as fp8. `experts/mtp.widths` is then 256 bytes of 8. The shared expert is the concatenation of gate and up, stored in `resident.bin` with the other resident matrices.

When `--expert-fp8` is greater than zero, the language projections, the token embedding, `lm_head`, the vision tower, and the shared expert are fp8 E4M3. The MTP shared expert is stored only by `mtp-fp8`, as fp8. The scale plane stays one E8M0 byte per 32 values along K. Routers, the shared-expert coefficient, norms, `A_log`, `dt_bias`, and the convolution taps stay float16. A finished directory has `manifest.json` with `complete: true` and the same `expert_fp8_percent`. Running quantize again on that directory returns it. An unfinished directory resumes from `quantize_progress.json` and requires `expert_error.json` when any expert is promoted.

`bf16` does not run a layer against the stored BF16 values.

## Forward

`serve` and `complete` apply the prompt in chunks of at most 2048 tokens, then sample one token at a time. `serve` draws a load row while the resident record and the expert images are read, then a prefill row that counts prompt tokens as each layer of a chunk finishes, then a decode row that counts sampled tokens as they are drawn. A streaming client receives each sampled token as a `chat.completion.chunk` with `id`, `object`, `created`, and `model`. Reasoning is `delta.reasoning_content` until `</think>`, and the reply is `delta.content`. The prefill clock starts at the uncached forward, after the prefix align, and ends when the first output token is sampled. The forward that produced that token's logits stays inside prefill. The prompt prefix write stays outside prefill. The decode clock starts at that same sample and ends at the last sample. A send between samples stays inside decode. The last send and the finished-sequence prefix write stay outside. `prompt_n` is the uncached prompt count. `predicted_n` is the completion count. A zero duration writes a rate of 0. Streaming and a single JSON completion both report `usage.timings` (`prompt_n`, `prompt_per_second`, `predicted_n`, `predicted_per_second`). Each row closes with that phase's tok/s line. A closed client stops the forward at the next layer. SIGINT and SIGTERM call `halt` and the process releases the runtime. A request that names another pipeline closes this runtime before that pipeline allocates. The close finishes the open command buffer, closes the expert files, and drops the device buffers. A chunk restores each resident language projection from its packed fp4 or fp8 bytes into a per-row int8 stage, quantizes the half activation the same way, and multiplies with a 64 by 64 int8 `matmul2d`. The stage holds one matrix and is dropped after the epilogue multiplies the int32 product by the token scale and the channel scale. Those matrices are the Gated DeltaNet qkv, z, and out projections, the attention q, k, v, and o projections, and the shared expert. `in_proj_a` and `in_proj_b` stay on the 64 by 32 packed tile. The router is a float16 matrix product. Routed experts stay on the packed fp4 and fp8 tiles. Decode reads the packed bytes with a GEMV and does not use the stage. Routed experts in the chunk are gathered into groups, multiplied, and scattered back onto the token rows. The sampled token is a GEMV. Routed expert groups for a chunk are built on device, in that layer's command buffer. The next layer is encoded while that buffer runs. One prefill of 8012 tokens ran at 1125 tok/s. Kernel and bandwidth ceilings for this forward are in [ceilings.md](ceilings.md). The isolated dispatch sum is a measurement in [research/kernel-ceilings.md](research/kernel-ceilings.md). Recorded prefill and decode rates are in [performance.md](performance.md). The file-agent sum is a measurement in [research/recorded-forward.md](research/recorded-forward.md).

The checkpoint position limit is `max_position_embeddings` (262,144). The served window stops at 131072 tokens. The live key/value cache starts at 2048 tokens and grows with the prompt and with decode, up to the longest multiple of 2048 that still leaves eight expert images. Each growth gives the new cache the bytes it needs, and the atlas keeps however many expert images fit in what remains. A prefill chunk whose routed experts do not fit that atlas applies them in groups of that size. On a machine where the full atlas and the full limit both fit, the atlas stays complete. The 10 language full-attention layers and the MTP layer share that context. The default width is fp8 E4M3. A key is one byte per channel with an E8M0 scale every 32 channels, contiguous across tokens. A value is one byte per channel along the token axis, with an E8M0 scale every 32 tokens. Prefill scores up to 4096 keys at a time on the 64 by 64 `matmul2d`, softmaxes those keys in parallel 256-key chunks, and mixes the values in one strided product. A one-token fp8 step packs the eight live query rows of a key/value head into one 8-row `matmul2d`, softmaxes 256-key chunks in parallel, and casts every 512-key block, mixes those blocks in one dispatch, and restores each block's peak. The value plane is read with the context length as its token stride. Softmax writes float32 weights on the score tile. Each value-mix window divides by that row's peak, multiplies in float16, then restores the peak, so a window below the running peak is not flushed to zero. The float16 flush bound for that cast is a measurement in [research/fp16-peak-restore.md](research/fp16-peak-restore.md). `e2m1` stores those planes as fp4 and uses the fp4 `matmul2d`. `f32` stores the float32 values with no quantization and keeps the float attention kernels. `serve` reads the registry row's `kv_cache`. `complete` takes `--kv-cache e4m3`, `--kv-cache e2m1`, or `--kv-cache f32`. A prompt that extends the live tokens continues from the first new token. Any other prompt writes that sequence through the shared prefix store and loads the longest stored strict prefix of the new tokens. The file holds the packed key and value positions for those 11 planes, the DeltaNet state, and the convolution history. The MTP plane is filled when the request drafts. An opening does not read `experts/mtp.bin` or the dense MTP suffix of `resident.bin`. A request with `mtp` true reads both before the draft. A request with `mtp` false releases that read. A draft reads its eight expert images from that buffer. A prefill chunk writes its MTP rows in one command buffer. The weight record does not store that cache. An exact-length file is not sampled; the next token is still stepped.

The runtime has one memory maximum. `serve --max-memory` and `complete --max-memory` set it, as a byte count or a `GiB` or `MiB` size. Omitting it uses the reclaimable memory at load. The resident record, the key/value cache, the state, and the chunk workspace are allocated inside that maximum. Language expert files stay on SSD. When the maximum holds all 40 × 256 images, each layer file is read once and the kernels index that buffer. The next token's layers are recorded while the current token's command buffer runs. When it holds fewer, a routed image that is not resident is read from its layer file into the atlas. A uniform record reads `slot × 1,671,168`. The file `experts/widths.bin` is 40 × 256 bytes and selects fp4 or fp8 for each routed expert. An fp8 image is 3,244,032 bytes at the offset in `experts/offsets.bin`. A missing width file, or a file of all fours, keeps the fp4 stride. The kernel adds that image's 64-bit byte offset to the atlas base. S3-FIFO (Yang, Zhang, Qiu, Yue, and Rashmi, SOSP 2023) keeps a second request and drops a one-hit, and a mixed image is evicted at its own length. An expert is not promoted or demoted to another quant. The shared expert stays at the width packed in `resident.bin`. A finished chat completion counts the router ids copied before `remap_expert_ids`. Prefill counts each uncached token. Decode counts each kept token once. Those integers stay in memory until the request closes. The listener then runs the lull, which writes one SQLite transaction at `~/.favlo/telemetry/<folder>/firing.sqlite`. A request that stops mid-forward is not written. The relative score over the newest 16384 complete tokens is that expert's hits divided by the layer's hits per expert. A uniform expert scores 1. The lull does not change a width. The shared expert stays in `resident.bin`.

A request field `mtp` wins when it is set. When the request omits it, the registry row is used, and a row that omits `mtp` is off. `mtp_depth` works the same way and is 3 when the row omits it. Neither field is read from the sampling card. `mtp` false keeps the serial sampler. True drafts one token from the MTP layer. The language forward then reads each dense weight once for that token and the draft. Later layers of that step are recorded while the earlier layers run. Gated DeltaNet and attention stay in token order. Routed experts stay on the token that selected them, and the shared expert is one weight read. `mtp_depth` above one does not widen that row. Temperature 0 keeps the draft when it is the target argmax. A sampled request reads those top candidates from the device, keeps the draft when a uniform draw falls under the target probability divided by the draft probability, and a miss draws from the positive remainder. A rejected draft restores the DeltaNet state and the convolution history to the copy taken after the confirmed token. A user image part runs the packed vision tower. The template writes one image pad, and that pad is expanded to the merged patch count. Those embedding rows are the tower output: a flattened Conv3d patch embed, a bilinear sample of the 48 by 48 position table in merge-block order, 27 blocks of LayerNorm, full attention, and a tanh-GELU MLP, then a merger that LayerNorms each patch, concatenates each 2 by 2 group, and applies erf GELU. The tower resizes a still so both sides are multiples of 32 and the pixel count stays inside the checkpoint processor, 65536 through 16777216. A chat image is an `image_url` part: an `http` or `https` URL, a `data:` URL, or base64. PNG, JPEG, GIF, and WebP decode to RGB. `detail` `low` uses the 65536-pixel budget. `auto`, `high`, and `original` use the full range. `min_pixels` and `max_pixels` on that part replace the budget and must sit inside the same edges. A text request leaves the vision weights idle. An audio part is not accepted by the template.

Full attention splits each head's 512 `q_proj` rows into 256 query rows and 256 gate rows. Partial RoPE covers the first 64 channels of each head. Channel i rotates with channel i+32, and the frequency of that pair is theta to the power -i/32. Text writes the same position on all three mRoPE axes. An image holds the temporal axis and writes height and width across the merged patch grid. The next text token continues from the longer side of that grid. Decode adds that prompt's position delta to the sequence index, so generated tokens keep one position on every axis. Expert gate-up uses the first 512 rows as the gate and the next 512 as the up projection. Those two splits are the kernel defaults. A BF16 layer has not accepted them.

The chat template is the checkout's `chat_template.jinja`. Thinking stays open unless the request sets `enable_thinking` false, which closes an empty think block in the prompt. A `reasoning_effort` field on the request is ignored. Temperature 0 is an argmax. A presence penalty is subtracted once from each distinct token already drawn in the completion. A frequency penalty is subtracted once for every earlier copy of that token. Both follow the OpenAI logit update. An omitted `max_tokens` does not cap the completion. It stops on a stop id or at the last context position. That room is the context ceiling. The cache grows during decode to reach it, and the atlas shrinks to the images that still fit. `settings.json` key `max_tokens` is that cap when the request omits it. A thinking budget is not applied unless that file sets `thinking_budget`. An instruct prompt already closed thinking, and `<think>` and `</think>` are not drawn again. A request that omits `max_tokens` and `max_completion_tokens` draws until the checkpoint context is full or a stop token is drawn. Either field caps the completion, and that cap cannot pass the context. A stop id ends the turn while that block is open. After that close, `</think>` is not drawn again. Stop ids are 248046 and 248044. A `tool_choice` of `none` leaves call text in the reply. A `tool_choice` that names one function closes thinking when the request did not set it. A named function renders the closed think in the prompt, then forces `<tool_call><function=name>` as the start of the completion. That is the template's empty reasoning turn, so the next prompt continues those tokens. A user message that follows a user or tool message with no assistant turn between them is rendered as that same empty turn, so the next prompt continues those tokens. A function with no parameters forces that call closed and does not sample past it. Earlier assistant turns keep the closed think block. A later message that sends `reasoning_content` re-renders that block and the reply, so the next prompt continues the stored tokens. When the token limit cuts an open think, a blank piece is dropped. The template trims that piece, and the stored prefix still matches the next prompt. The reply parser turns a finished call into an OpenAI `tool_calls` message. The call XML is not sent as `delta.content`. A parameter body that is a JSON array, object, or number is that value. Any other body stays a string. A leading zero keeps a digit string as text. A `\uXXXX` escape in that string, in the reply, and in the reasoning becomes that character. The same escape inside a JSON array or object is left for the JSON parse.

Harness scores for this pipeline are in [benchmarks.md](benchmarks.md). `complete` writes one greedy carrot completion to `carrots.json` in the record directory. `tests/test_qwen36_35b_a3b_smoke.py` runs that prompt on this pipeline, once at temperature 0 and once at the instruct card. The reply collects 6 carrots. Thinking runs at the thinking card when the checkpoint template opens a think block. `tests/test_qwen36_35b_a3b_smoke_16gb.py` is skipped for now. It would run those same cases with the runtime capped at 16GiB, so the atlas holds fewer than every expert image. `models` reads the shared registry. Registration copies the thinking and instruct rows from `sampling.py`: thinking temperature 1.0, top-p 0.95, top-k 20, presence penalty 1.5; instruct temperature 0.7, top-p 0.8, top-k 20, presence penalty 1.5. A request that omits the variant uses the thinking row, including presence penalty 1.5. `enable_thinking` false uses the instruct row from that card. The precise-coding preset (temperature 0.6, top-p 0.95, top-k 20, presence penalty 0) stays in `sampling.py`. The registry has no third variant name, so registration does not store it.
