# Qwen3.6-35B-A3B

As-built note for the `qwen36-35b-a3b` pipeline. The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

Clients reach this pipeline through `madmetal serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `kernels`, `quantize`, `bf16`, `complete`, and `models` require `madmetal --qwen36-35b-a3b`. That flag loads `qwen36-35b-a3b.py`, which loads `qwen36_35b_a3b`. The package does not import `qwen38_flash_next` or `qwen38_27b`.

## Kernels

`kernels` compiles this package's shader library and fails if any kernel in that library does not produce a pipeline. It then dispatches the fp4 and fp8 `matmul2d` tiles, the fp4 GEMV, the 32-row projection, the float16 GEMV at 1 row and at 256 rows, one fp4 expert image of 1,671,168 bytes, the expert-slot remap, the vision `linear_fc1` pad (4320 by 1280, 16 rows dropped), the head-72 online softmax, the tanh GELU, one Gated DeltaNet step, and the 8192-channel convolution. The same command checks that a repeated think clause is not drawn again. The host formulas for those dispatches live in `qwen36_35b_a3b/checks.py`.

The DeltaNet state is float32, 32 heads of `128×128`. The step decays the state by \(\alpha\), writes \(\beta(v - Sk)k^\top\), and reads with the query. Decode does that once per token. Prefill uses the same recurrence in chunks of 64 (Yang et al., Gated Delta Networks, §3.3), so the state update and the outputs run across the chunk and the 32 heads. The short convolution is one thread per token and channel. It reads the raw projection, including the three taps kept from the previous chunk, and writes the mixed values beside that projection. The output norm multiplies by the stored weight, then the output gate is SiLU. Query repeat is 2, the mixed vector is 8192 wide, and the gate is 4096 wide. Float16 vectors are cast to float in the shader that reads them. This form is what `kernels` checks. A BF16 layer step has not accepted it.

## Record

`quantize` streams a Hugging Face BF16 checkout into `models/<name>-fp4`. With no `--src`, it reads `models/Qwen3.6-35B-A3B-bf16` and writes `models/Qwen3.6-35B-A3B-fp4`. `--src` names another checkout. `<name>` is then the repository name when that source is a hub snapshot, and the directory name otherwise. Routed experts, the shared expert, and the MTP expert block are uniform fp4 E2M1 with an E8M0 scale every 32 along K. Each routed expert is one 1,671,168-byte image: gate-up `[1024, 2048]` then down `[2048, 512]`. Inside a layer file the 256 images are ordered by the median E8M0 byte of that image. Ties keep the lower checkpoint row in the earlier slot. The scale bytes move with the image and are not merged. `experts/order.bin` holds 40 maps of 256 bytes. `map[router row]` is the slot in that layer's file. The router matrix stays in checkpoint order. `remap_expert_ids` rewrites the eight selected ids before `moe_group` and before the decode expert kernels. Language experts are `experts/<layer>.bin`. MTP routed experts are `experts/mtp.bin`, ordered the same way, with the map in `experts/mtp.order`. The MTP block is not drafted. The shared expert is the concatenation of gate and up, stored in `resident.bin` with the other resident matrices. Layer order is unchanged.

Routers, the shared-expert coefficient, norms, `A_log`, `dt_bias`, and the convolution taps stay float16. Every other matrix, including the embedding and `lm_head`, is fp4. A finished directory has `manifest.json` with `complete: true`. Running quantize again on that directory returns it. An unfinished directory resumes from `quantize_progress.json`.

`bf16` does not run a layer against the stored BF16 values.

## Forward

`serve` and `complete` apply the prompt in chunks of at most 2048 tokens, then sample one token at a time. `serve` draws a prefill row that counts prompt tokens as each layer of a chunk finishes, then a decode row that counts sampled tokens as they are drawn. A streaming client receives each sampled token as a `chat.completion.chunk` with `id`, `object`, `created`, and `model`. Reasoning is `delta.reasoning_content` until `</think>`, and the reply is `delta.content`. The chunk before `data: [DONE]` carries `usage.timings` (`prompt_n`, `predicted_n`, `predicted_per_second`). Each row closes with that phase's tok/s line. A closed client stops the forward at the next layer. SIGINT and SIGTERM call `halt` and the process releases the runtime. A chunk's projections are fp4 `matmul2d` tiles: 64 by 64 where the output width is a multiple of 64, and 64 by 32 otherwise. The router is a float16 matrix product. Routed experts in the chunk are gathered into groups, multiplied, and scattered back onto the token rows. The sampled token is a GEMV. Routed expert groups for a chunk are built on device, in that layer's command buffer. The next layer is encoded while that buffer runs. One prefill of 8012 tokens ran at 1125 tok/s. Kernel and bandwidth ceilings for this forward are in [ceilings.md](ceilings.md). Recorded prefill and decode rates are in [performance.md](performance.md).

The position limit is the checkpoint's `max_position_embeddings` (262,144). The live key/value cache covers that limit for the 10 full-attention layers. The default width is fp8 E4M3. A key is one byte per channel with an E8M0 scale every 32 channels, contiguous across tokens. A value is one byte per channel along the token axis, with an E8M0 scale every 32 tokens. Prefill scores up to 4096 keys at a time on the 64 by 64 `matmul2d`, softmaxes those keys in parallel 256-key chunks, and mixes the values in one strided product. A one-token fp8 step packs the eight live query rows of a key/value head into one 8-row `matmul2d`, softmaxes 256-key chunks in parallel, and reduces the value mix in blocks of 512 keys. The value plane is read with the context length as its token stride. Softmax writes float32 weights on the score tile. Each value-mix window divides by that row's peak, multiplies in float16, then restores the peak, so a window below the running peak is not flushed to zero. `e2m1` stores those planes as fp4 and uses the fp4 `matmul2d`. `f32` stores the float32 values with no quantization and keeps the float attention kernels. `serve` reads the registry row's `kv_cache`. `complete` takes `--kv-cache e4m3`, `--kv-cache e2m1`, or `--kv-cache f32`. A prompt that extends the live tokens continues from the first new token. Any other prompt writes that sequence through the shared prefix store and loads the longest stored strict prefix of the new tokens. The file holds the packed key and value positions for the 10 full-attention layers, the DeltaNet state, and the convolution history. The weight record does not store that cache. An exact-length file is not sampled; the next token is still stepped.

The runtime has one memory maximum. `serve --max-memory` and `complete --max-memory` set it, as a byte count or a `GiB` or `MiB` size. Omitting it uses the reclaimable memory at load. The resident record, the key/value cache, the state, and the chunk workspace are allocated inside that maximum. Language expert files stay on SSD. The atlas keeps as many whole layer files as the remaining bytes hold, and never more than the 40 layer files. A layer that does not fit is read into the least recently used slot when that layer runs. The shared expert stays in `resident.bin`.

The MTP block is packed and is not drafted, so the sampled token is the backbone token. Vision weights are packed when the checkout has them. A text request does not run the tower. An audio part is not accepted by the template.

Full attention splits each head's 512 `q_proj` rows into 256 query rows and 256 gate rows. Partial RoPE covers the first 64 channels of each head. Channel i rotates with channel i+32, and the frequency of that pair is theta to the power -i/32. Text writes the same position on all three mRoPE axes. Expert gate-up uses the first 512 rows as the gate and the next 512 as the up projection. Those two splits are the kernel defaults. A BF16 layer has not accepted them.

The chat template is the checkout's `chat_template.jinja`. Thinking stays open unless the request sets `enable_thinking` false, which closes an empty think block in the prompt. Temperature 0 is an argmax. A presence penalty is subtracted once from each distinct token already drawn in the completion. A frequency penalty is subtracted once for every earlier copy of that token. Both follow the OpenAI logit update. An omitted `max_tokens` does not cap the completion. It stops on a stop id or at the last context position. `settings.json` key `max_tokens` is that cap when the request omits it. A thinking budget is not applied unless that file sets `thinking_budget`. While `<think>` is open, a token that would repeat a 5-token span starts the template close. The same word, with one token between the copies, does the same. A markdown marker is not that word. A token whose piece contains 7 or more letters, drawn again, does the same, unless that token is already in the prompt. The GPT-2 space marker in a stored piece is not a letter. An instruct prompt already closed thinking, and `<think>` and `</think>` are not drawn again. After the close, any of those repeats is not drawn, and another token is sampled. A tool call is left as drawn, and a repeated span inside that call stays. A second tool call in the same completion is not drawn. An 8-token span already drawn cannot be drawn again: the token that would complete it is removed (Paulus, Xiong, and Socher, n-gram blocking). A request that omits `max_tokens` and `max_completion_tokens` draws until the checkpoint context is full or a stop token is drawn. Either field caps the completion, and that cap cannot pass the context. A stop id drawn while that block is open is the same close sequence. After that close, `</think>` is not drawn again. Stop ids are 248046 and 248044. A `tool_choice` of `none` leaves call text in the reply. A `tool_choice` that names one function closes thinking when the request did not set it. A named function renders the closed think in the prompt, then forces `<tool_call><function=name>` as the start of the completion. That is the template's empty reasoning turn, so the next prompt continues those tokens. A function with no parameters forces that call closed and does not sample past it. Earlier assistant turns keep the closed think block. A later message that sends `reasoning_content` re-renders that block and the reply, so the next prompt continues the stored tokens. When the token limit cuts an open think, a blank piece is dropped. The template trims that piece, and the stored prefix still matches the next prompt. The reply parser turns a finished call into an OpenAI `tool_calls` message, and the call XML is also sent as `delta.content` so that text can be echoed.

Harness scores for this pipeline are in [benchmarks.md](benchmarks.md). `complete` writes one greedy carrot completion to `carrots.json` in the record directory. `tests/test_qwen36_35b_a3b_smoke.py` runs that prompt on this pipeline, once at temperature 0 and once at the instruct card. The reply collects 6 carrots. Thinking runs at the thinking card when the checkpoint template opens a think block. Each reasoning effort that template names is its own case. `models` reads the shared registry. Registration copies the thinking and instruct rows from `sampling.py`: thinking temperature 1.0, top-p 0.95, top-k 20, presence penalty 1.5; instruct temperature 0.7, top-p 0.8, top-k 20, presence penalty 1.5. A request that omits the variant uses the thinking row, including presence penalty 1.5. `enable_thinking` false uses the instruct row from that card. The precise-coding preset (temperature 0.6, top-p 0.95, top-k 20, presence penalty 0) stays in `sampling.py`. The registry has no third variant name, so registration does not store it.
