# Qwen3.8 schedule

As-built prefill, decode, and pack path for Qwen3.8-Flash-Next. File layout is in [record.md](record.md). Scope is in [ARCHITECTURE.md](../../ARCHITECTURE.md). If this note disagrees with that file, ARCHITECTURE.md wins.

Prefill and decode run as Metal shaders on the Apple Silicon GPU. There is no host GEMV on this path, and a kernel that is not written yet is not replaced by one.

`madmetal --qwen38-flash-next bf16` runs this same forward on the Hugging Face BF16 checkpoint. Each linear map is a float32 shader dot of the exact stored value. Dense matrices are uploaded once. An expert and an n-gram row are read from the shards when that token needs them. The command isolates the formula from the int4 record. `bf16` and `complete` leave thinking off unless `--thinking` is set. `serve` leaves `<think>` open when the request omits `enable_thinking`, so decode writes the reasoning. `--raw` tokenizes the prompt with no chat template. `complete` accepts the same flag and reads the int4 record. Shard reads bypass the file cache. An expert's float weights leave the cache at the end of that layer. The command buffer that used them stays open until the next expert-id read. `serve` and `complete` still read the record and do not open those shards.

`madmetal --qwen38-flash-next quantize` writes the record from the Hugging Face BF16 shards. `--hot` is the keep-set JSON, layer index to expert ids. `--super` is the int8 pin, a list of layer and expert ids that must sit inside that keep set. The pin is packed int8 into `experts/NN-super.bin` when the layer has one. The rest of the keep set is packed int4 into `experts/NN-hot.bin`. The complement of the keep set is packed int2 into `experts/NN-cold.bin`. MTP experts stay one int4 file. The n-gram table stays one int4 table. That command is the only place a weight is quantized. `resident.bin` is written and sealed before any expert worker starts. A pool of four workers then packs layers. Each worker reads that layer's shards once, writes the tier files, and `fsync`s them. The parent is the only writer of `quantize_progress.json`. A layer is finished only after that `fsync`. A crash redoes a layer that is absent from the finished set, from the first expert. N-gram workers start after the expert pool and the MTP file. One worker reads one safetensors file and writes that file's tensors at their fixed offsets. Progress for the table is the set of finished tensors. `manifest.json` is written last, with `complete: true` and record version 4. The command then runs one greedy completion of the grove prompt on that record, with thinking off, and writes the prompt and the text to `grove.json`. When this run packed the record, that file is written again. When the record is already complete, quantize leaves the packed files in place and writes `grove.json` only when the file is absent. The smoke test reads that file and checks a new greedy completion against the stored text. The completion that returned before this file existed was packed during the request.

A prompt chunk whose token count is greater than one runs an int4 map through `mpp::tensor_ops::matmul2d` when the row count is a multiple of 32 and the inner dimension is the stored width. A super expert, including a group of many tokens, uses `gemv_int8_f32` on the gate and `gemv_int8_half` on the down projection. The half × int8 `matmul2d` kernel compiles, and its dispatch does not complete on this GPU, so it is not on the request path. The right operand is the quantized weight with its E8M0 scale plane. That plane requires `transpose_right`. The tile is 64 by 32, four simdgroups per threadgroup. The activation is float16. The destination is float32, which is what the measured kernel writes. The batch is padded up to a multiple of 64 and the padded rows are dropped. A matrix that misses either condition uses a batched shader dot. A single-token int4 map uses `gemv_int4_f32`: four rows per simdgroup, each lane reading its own 32-wide block, with the SiLU and sigmoid epilogues in that kernel.

Decode int4 maps are that GEMV. Gated DeltaNet is one convolution scan and one state scan for the chunk. Sparse attention projects the chunk, then attends. A query inside the dense window attends every visible token. A longer query attends the selected blocks. Each head and token is one threadgroup, and sixteen simdgroups split that token's keys and values. Each lane reads eight consecutive channels of that head. A prompt that fits in one chunk groups routed experts by tier so one expert's weights are applied to the tokens that selected it. A longer prompt keeps each token's mixer output, then runs every int4 expert that received at least 64 tokens through matmul2d. The int2 tier and any smaller int4 group stay on the grouped shader. A prompt call does not read the atlas. An atlas from an earlier decode stays allocated when the staging buffers fit beside it. It reads that layer's `NN-hot.bin` and `NN-cold.bin` in full, in row order, through uncached Metal IO into one of two staging buffers. On a short prompt the next layer is submitted when the current layer's expert kernels are encoded. On a longer prompt it is submitted at the start of the layer so the read overlaps the mixer. The grouped shader reads `row × stride` inside the staging buffer. Super experts stay in their resident int8 buffers. After the prompt call the staging buffers are released. An atlas from an earlier decode stays allocated when those buffers fit beside it. A cold start allocates the atlas after the call. If the device refuses the staging buffers, that atlas is released and allocated again after the call. A decode token reads the ten ids, stages any missing run in each tier, and then runs the gate and down kernels once per tier those ids touch. The cold tier adds onto the hot result, and a routed super expert adds onto that sum from its resident int8 image. An id that belongs to another tier is not a miss. Prefill steps each layer's mixer in chunks of 2048 tokens and rewinds one scratch arena after each chunk, so that layer's hot and cold files are read once. On the n-gram layer, a longer prompt finishes that chunk's page loads and the shaders that read them before the next rewind. Those loads land in the scratch arena. A longer prompt applies the routed experts once after those chunks. That arena is 2 MiB per token in the chunk, or 256 MiB, whichever is larger. A scratch or cache allocation the device refuses raises. Decode keeps two arenas: the expert kernels and the residual write are committed after that layer, and the next layer encodes into the other arena while those kernels run. The prefill scratch is released before those arenas are allocated. The residual stays in its own buffer. RMSNorm, SiLU, sigmoid, softplus, L2 norm, RoPE, both depthwise convolutions, residual adds, the branch mean, and the router softmax and top-10 are shaders in that same command buffer. Hyper-connection norms are Gemma-style, `x / rms · (1 + w)`. The GDN head norm is the multiplicative form, `x / rms · w`, with the sigmoid output gate applied after it. Q and K are L2-normalized, and Q is then scaled by `1/√128`. The attention query projection splits into the query and a sigmoid gate. Activations stay in device buffers. The dependence is the embedding, then for each of the 48 layers a residual read, a mixer, a residual write, the router, the shared expert, and up to ten routed experts. Layer 1 adds the n-gram injection into the four residual branches before its mixer. The output head runs once, on the last token of the chunk. MTP does not run. K and V default to E4M3 on each completed block of four, with an E8M0 scale every 32 channels, and the unfinished tail stays BF16. `--kv-cache bf16` stores every K and V token as BF16. The indexer key is BF16 in both modes. `serve`, `complete`, and `bf16` take that switch. The log reports the end-to-end rate and an after-load rate. End-to-end divides tokens by wall time, including the prefill file read and the atlas fill. Prefill's after-load rate divides the prompt tokens by GPU time, which starts once that command buffer's file wait has finished. Decode's after-load rate starts on the first step whose resident count does not grow, and reports that window's wall time and its GPU time. A prefix hit that steps nothing logs prefill as zero tokens. `complete`, `bf16`, and `serve` accept `--transcript`. That file receives the prompt and the completion. Token rates stay on the console.

The host commits a command buffer when the next load needs a value that buffer will produce. These steps stay on the host:

- The chat template and the tokenizer emit token ids. Those ids are copied into the buffer the embedding gather reads.
- The n-gram mix is sixteen wrapping int64 XORs of token ids the host already stores. Each result selects a 128-byte slot. A single token loads the 16 KB page that contains that slot through Metal IO into a small page cache, and a shader reconstructs the row. A chunk of at least 256 tokens computes those ids in one segment scan and expands every slot from the pages that chunk loads. That packed destination offset is a multiple of the 16 KB page. A prompt longer than one chunk finishes those loads before the next chunk rewinds the arena. The multipliers, head offsets, and vocabulary sizes are 280 bytes of int64 at the tail of `resident.bin`, copied out of that buffer once after it loads. The formula is in [ngram.md](ngram.md).
- The sampler keeps a top-k of at most 32 on 1024 threads, then draws from that list. Temperature 0 still uses the parallel argmax. The router shader writes ten expert ids and ten weights. The host reads the ten ids, once per layer, on prefill and on a decode token whose experts are not yet known to be resident. On a short prompt it waits for the layer file submitted earlier, encodes the grouped kernels, and submits the next layer. On a longer prompt it submits the next file at the start of the layer and reads the router ids once for the whole layer before the expert kernels. On an untrusted decode token it stages any missing run before that layer's expert kernels. The previous token's ids for every layer are already in flight, so a hit does not read the file and a later layer's load overlaps this layer's mixer. The atlas is allocated after the first prompt call and kept across a later prompt when the staging buffers fit beside it. `--resident-percent` requests that share of the hot-tier bytes and steps down by 4 GiB until 8 GiB. Omitting it tries 24 GiB, then 20, 16, 12, and 8. After a decode token whose routed experts were all resident, the next token leaves those ids on the device. The expert kernels run in the same command buffer as the mixer, and the host reads the ids once at the end of the token. A miss loads the missing experts and replays that token from the recurrent snapshot. The weights stay on the device. On the untrusted path that per-layer read ends the command buffer that produced the ids, and the expert kernels are committed with the residual write, without waiting, so the GPU runs them while the host encodes the next layer.
- Sampling returns one token id. Temperature at or below zero is a GPU argmax. A positive temperature builds the probability vector and walks the CDF on the GPU; the host passes in one uniform draw. A token span that has already been emitted three times is removed from that draw, as is a recent window that uses only a handful of distinct tokens. A presence penalty, when the request sets one, is subtracted once from each token already written. A frequency penalty is subtracted once for every earlier copy of that token. The id is the stop check, the prefix-cache key, and the next step's token. While a function name is open, or a `tool_choice` names one function, the draw is limited to the tokens described in ARCHITECTURE.md.
- The converter packs on the host because that command writes the file the shaders read.
- `bf16` reads a shard row for an expert or an n-gram vector, uploads it, and then uses these shaders. `serve` and `complete` do not open those shards.

Missing decode ids are sorted, and each run of consecutive ids is one sequential load of `(last − first + 1) × live` bytes from file offset `first × live` into one resident atlas. The destination offset in that atlas is the same multiple of 16 KB. An int64 table stores each image base, and an empty entry is −1. The shader reads the live bytes at that base. A run that does not intersect the ids being staged can be evicted. The IO queue is concurrent, and each IO buffer waits for the previous signal before its loads, so a later event value means the earlier loads have finished. An expert or n-gram load signals that shared event, and the compute command buffer waits on the value for the image it is about to read. A decode step submits the previous token's ids for every layer before the first mixer, and each layer waits only for its own signal, so later loads stay in flight while earlier layers run.

A resident hit on decode does not read the file. A prompt call reads every hot and cold image in the layer, so its transfer size is those tier files. Matrices loaded once are read at startup into one shared buffer. Their per-token path does not return to the SSD.

The router stays float16 and uses its own shader dot. The token embedding is one int4 row, gathered and reconstructed. A query whose visible length fits in the dense attend kernel attends every token. A longer query scores each complete block of 4 indexer keys, the mean of the block then the sum of ReLU dots over the 4 query heads, and attends the top 512 blocks plus the unfinished tail. One token reduces that dot across the threadgroup, adding dimensions in order. The top 512 is one threadgroup per query: each thread owns a contiguous run of blocks, and the histogram and the index-ordered collect match the host radix, so a tie keeps the lower block index. The attend reads K and V from the cache: a completed E4M3 token is dequantized per 32 channels, and a BF16 token is expanded from the stored bits. The sparse attend takes that mode from a device word. The prompt length is the tokens that fit after the resident hot-expert budget, and at most 131,072. A prompt past that limit is refused, and generation stops when the next token would pass it.
