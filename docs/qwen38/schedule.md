# Qwen3.8 schedule

As-built prefill, decode, and pack path for Qwen3.8-Flash-Next. File layout is in [record.md](record.md). Scope is in [ARCHITECTURE.md](../../ARCHITECTURE.md). If this note disagrees with that file, ARCHITECTURE.md wins.

Prefill and decode run as Metal shaders on the Apple Silicon GPU. There is no host GEMV on this path, and a kernel that is not written yet is not replaced by one.

`madmetal --qwen38-flash-next bf16` runs this same forward on the Hugging Face BF16 checkpoint. Each linear map is a float32 shader dot of the exact stored value. Dense matrices are uploaded once. An expert and an n-gram row are read from the shards when that token needs them. The command isolates the formula from the int4 record. Thinking stays off unless `--thinking` is set, matching the server. `--raw` tokenizes the prompt with no chat template. `complete` accepts the same flag and reads the int4 record. Shard reads bypass the file cache. An expert's float weights leave the cache at the end of that layer. The command buffer that used them stays open until the next expert-id read. `serve` and `complete` still read the record and do not open those shards.

`madmetal --qwen38-flash-next quantize` writes the record from the Hugging Face BF16 shards. `--hot` is the keep-set JSON, layer index to expert ids. `--super` is the int8 pin, a list of layer and expert ids that must sit inside that keep set. The pin is packed int8 into `experts/NN-super.bin` when the layer has one. The rest of the keep set is packed int4 into `experts/NN-hot.bin`. The complement of the keep set is packed int2 into `experts/NN-cold.bin`. MTP experts stay one int4 file. The n-gram table stays one int4 table. That command is the only place a weight is quantized. `resident.bin` is written and sealed before any expert worker starts. A pool of four workers then packs layers. Each worker reads that layer's shards once, writes the tier files, and `fsync`s them. The parent is the only writer of `quantize_progress.json`. A layer is finished only after that `fsync`. A crash redoes a layer that is absent from the finished set, from the first expert. N-gram workers start after the expert pool and the MTP file. One worker reads one safetensors file and writes that file's tensors at their fixed offsets. Progress for the table is the set of finished tensors. `manifest.json` is written last, with `complete: true` and record version 4. The command then runs one greedy completion of the grove prompt on that record, with thinking off, and writes the prompt and the text to `grove.json`. When this run packed the record, that file is written again. When the record is already complete, quantize leaves the packed files in place and writes `grove.json` only when the file is absent. The smoke test reads that file and checks a new greedy completion against the stored text. The completion that returned before this file existed was packed during the request.

A prompt chunk whose token count is greater than one runs an int4 map through `mpp::tensor_ops::matmul2d` when the row count is a multiple of 32 and the inner dimension is the stored width. A super expert, including a group of many tokens, uses `gemv_int8_f32` on the gate and `gemv_int8_half` on the down projection. The half × int8 `matmul2d` kernel compiles, and its dispatch does not complete on this GPU, so it is not on the request path. The right operand is the quantized weight with its E8M0 scale plane. That plane requires `transpose_right`. The tile is 64 by 32, four simdgroups per threadgroup. The activation is float16. The destination is float32, which is what the measured kernel writes. The batch is padded up to a multiple of 64 and the padded rows are dropped. A matrix that misses either condition uses a batched shader dot. A single-token int4 map uses `gemv_int4_f32`: four rows per simdgroup, each lane reading its own 32-wide block, with the SiLU and sigmoid epilogues in that kernel.

Decode int4 maps are that GEMV. Gated DeltaNet is one convolution scan and one state scan for the chunk. Sparse attention projects the chunk, then one attend kernel. That kernel splits the visible keys and values across sixteen simdgroups. Routed experts in a prompt chunk are grouped by tier so one expert's weights are applied to the tokens that selected it. A prompt call does not hold the atlas. It reads that layer's `NN-hot.bin` and `NN-cold.bin` in full, in row order, through uncached Metal IO into one of two staging buffers. The next layer is submitted when the current layer's expert kernels are encoded. The grouped shader reads `row × stride` inside the staging buffer. Super experts stay in their resident int8 buffers. After the prompt call those buffers are released and the atlas is allocated. A decode token reads the ten ids, stages any missing run in each tier, and then runs the gate and down kernels once per tier those ids touch. The cold tier adds onto the hot result, and a routed super expert adds onto that sum from its resident int8 image. An id that belongs to another tier is not a miss. Prefill rewinds one scratch arena after the layer. That arena is 2 MiB per token in the chunk, or 256 MiB, whichever is larger. Decode keeps two arenas: the expert kernels and the residual write are committed after that layer, and the next layer encodes into the other arena while those kernels run. The residual stays in its own buffer. RMSNorm, SiLU, sigmoid, softplus, L2 norm, RoPE, both depthwise convolutions, residual adds, the branch mean, and the router softmax and top-10 are shaders in that same command buffer. Hyper-connection norms are Gemma-style, `x / rms · (1 + w)`. The GDN head norm is the multiplicative form, `x / rms · w`, with the sigmoid output gate applied after it. Q and K are L2-normalized, and Q is then scaled by `1/√128`. The attention query projection splits into the query and a sigmoid gate. Activations stay in device buffers. The dependence is the embedding, then for each of the 48 layers a residual read, a mixer, a residual write, the router, the shared expert, and up to ten routed experts. Layer 1 adds the n-gram injection into the four residual branches before its mixer. The output head runs once, on the last token of the chunk. MTP does not run. Under the BF16 default, every sparse-attention token's K and V are kept, and the indexer key is kept beside them. The fp8 KV switch is not selected by the server. The log reports the end-to-end rate and an after-load rate. End-to-end divides tokens by wall time, including the prefill file read and the atlas fill. Prefill's after-load rate divides the prompt tokens by GPU time, which starts once that command buffer's file wait has finished. Decode's after-load rate starts on the first step whose resident count does not grow, and reports that window's wall time and its GPU time. A prefix hit that steps nothing logs prefill as zero tokens. `complete`, `bf16`, and `serve` accept `--transcript`. That file receives the prompt and the completion. Token rates stay on the console.

The host commits a command buffer when the next load needs a value that buffer will produce. These steps stay on the host:

- The chat template and the tokenizer emit token ids. Those ids are copied into the buffer the embedding gather reads.
- The n-gram mix is sixteen wrapping int64 XORs of token ids the host already stores. Each result selects a 128-byte slot. The request path loads the 16 KB page that contains that slot through Metal IO into a small page cache, and a shader reconstructs the row. The multipliers, head offsets, and vocabulary sizes are 280 bytes of int64 at the tail of `resident.bin`, copied out of that buffer once after it loads. The formula is in [ngram.md](ngram.md).
- The sampler keeps a top-k of at most 32 on 1024 threads, then draws from that list. Temperature 0 still uses the parallel argmax. The router shader writes ten expert ids and ten weights. The host reads the ten ids, once per layer. On a prompt call it waits for the layer file submitted earlier, encodes the grouped kernels, and submits the next layer. On decode it stages any missing run before that layer's expert kernels. The atlas is allocated after the prompt call and tries 24 GiB, then 20, 16, 12, and 8. The weights stay on the device. That read ends the command buffer that produced the ids. On decode the expert kernels are committed with the residual write, without waiting, so the GPU runs them while the host encodes the next layer.
- Sampling returns one token id. Temperature at or below zero is a GPU argmax. A positive temperature builds the probability vector and walks the CDF on the GPU; the host passes in one uniform draw. The id is the stop check, the prefix-cache key, and the next step's token. While a function name is open, or a `tool_choice` names one function, the draw is limited to the tokens described in ARCHITECTURE.md.
- The converter packs on the host because that command writes the file the shaders read.
- `bf16` reads a shard row for an expert or an n-gram vector, uploads it, and then uses these shaders. `serve` and `complete` do not open those shards.

Missing decode ids are sorted, and each run of consecutive ids is one sequential load of `(last − first + 1) × live` bytes from file offset `first × live` into one resident atlas. The destination offset in that atlas is the same multiple of 16 KB. An int64 table stores each image base, and an empty entry is −1. The shader reads the live bytes at that base. A run that does not intersect the ids being staged can be evicted. The IO queue is concurrent, and each IO buffer waits for the previous signal before its loads, so a later event value means the earlier loads have finished. An expert or n-gram load signals that shared event, and the compute command buffer waits on the value for the image it is about to read. A decode step submits the previous token's ids for every layer before the first mixer, and each layer waits only for its own signal, so later loads stay in flight while earlier layers run.

A resident hit on decode does not read the file. A prompt call reads every hot and cold image in the layer, so its transfer size is those tier files. Matrices loaded once are read at startup into one shared buffer. Their per-token path does not return to the SSD.

The router stays float16 and uses its own shader dot. The token embedding is one int4 row, gathered and reconstructed. Sequences at or under the 2048-token budget attend every token, which is the QSA rule when every complete block fits in the budget. A longer sequence stops, because the sparse block mask is not a kernel in this path yet.
