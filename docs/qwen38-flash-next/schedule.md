# Qwen3.8 schedule

As-built prefill, decode, and pack path for Qwen3.8-Flash-Next. File layout is in [record.md](record.md). Scope is in [ARCHITECTURE.md](../../ARCHITECTURE.md). If this note disagrees with that file, ARCHITECTURE.md wins.

Prefill and decode run as Metal shaders on the Apple Silicon GPU. There is no host GEMV on this path, and a kernel that is not written yet is not replaced by one.

`madmetal --qwen38-flash-next bf16` runs this same forward on the Hugging Face BF16 checkpoint. Each linear map is a float32 shader dot of the exact stored value. Dense matrices are uploaded once. An expert and an n-gram row are read from the shards when that token needs them. The command isolates the formula from the int4 record. `bf16` and `complete` leave thinking off unless `--thinking` is set. `serve` leaves `<think>` open when the request omits `enable_thinking`, so decode writes the reasoning. A request that sets `enable_thinking` false keeps the open tag out of the draw. `--raw` tokenizes the prompt with no chat template. `complete` accepts the same flag and reads the int4 record. Shard reads bypass the file cache. An expert's float weights leave the cache at the end of that layer. The command buffer that used them stays open until the next expert-id read. `serve` and `complete` still read the record and do not open those shards.

`madmetal --qwen38-flash-next quantize` writes the record from the Hugging Face BF16 shards. It reads `quant_map.json`. `experts` is one width per expert, and `super` is the pin. The shipped map is 48 rows of 512, every width 4. `super` is the atlas pin, and those images stay in the fp4 file. The runtime serves that width. `--quant-map` selects another file. `--mtp-bits` defaults to 4. Each layer of the served record is `experts/NN-fp4.bin`, with the experts in id order. The n-gram table stays one fp4 table. That command is the only place a weight is quantized. `resident.bin` is written and sealed before any expert worker starts. A pool of four workers then packs layers. Each worker reads that layer's shards once, writes the tier files, and `fsync`s them. The parent is the only writer of `quantize_progress.json`. A layer is finished only after that `fsync`. A crash redoes a layer that is absent from the finished set, from the first expert. N-gram workers start after the expert pool and the MTP file. One worker reads one safetensors file and writes that file's tensors at their fixed offsets. Progress for the table is the set of finished tensors. `manifest.json` is written last, with `complete: true` and record version 6. The command then runs one greedy completion of the grove prompt on that record, with thinking off, and writes the prompt and the text to `grove.json`. When this run packed the record, that file is written again. When the record is already complete, quantize leaves the packed files in place and writes `grove.json` only when the file is absent. The smoke test reads that file and checks a new greedy completion against the stored text. The completion that returned before this file existed was packed during the request.

A prompt chunk whose token count is greater than one runs the fp4 map through `mpp::tensor_ops::matmul2d` when the row count is a multiple of 32 and the inner dimension is the stored width. The right-hand type is `metal_fp4_e2m1`, with the E8M0 scale plane. A pinned expert is an fp4 image in the atlas and uses the same fp4 matmul or GEMV. The half × int8 `matmul2d` kernel compiles, and its dispatch does not complete on this GPU, so it is not on the request path. The right operand is the quantized weight with its E8M0 scale plane. That plane requires `transpose_right`. The tile is 64 by 32, four simdgroups per threadgroup. The activation is float16. The destination is float32, which is what the measured kernel writes. The batch is padded up to a multiple of 64 and the padded rows are dropped. A matrix that misses either condition uses a batched shader dot. A single-token fp4 map uses `gemv_int4_f32`: four rows per simdgroup, each lane reading its own 32-wide block, with the SiLU and sigmoid epilogues in that kernel.

Decode of an fp4 expert is that GEMV. A span of two to four tokens runs matmul2d for its int4 projections. The one-token projection stays the GEMV. Gated DeltaNet is one convolution scan and one state scan for the chunk. Sparse attention projects the chunk, then attends. A query inside the dense window attends every visible token. A longer query attends the selected blocks. Each key/value head and token is one threadgroup. The twelve query heads that share it reuse that key and that value. Eight keys and eight values are loaded before the next barrier. Each lane reads eight consecutive channels. The fp4 expert dot uses the same launch as that GEMV: four simdgroups, four rows each. After a layer's mixer chunks, the experts that layer routed are loaded into the atlas. An expert selected by at least 64 tokens is applied with matmul2d on that resident image for the whole layer. A smaller group stays on the grouped shader, which reads the same atlas. Decode of one expert uses the fp4 GEMV on the atlas image. The record this tree serves is version 6. Every expert is fp4 in `experts/NN-fp4.bin`. The super list is the atlas pin, loaded from that file and left resident. `quantize` writes that version 6 record from `quant_map.json`. Every prefill loads each miss into the atlas and records a repeated selection so S3-FIFO keeps that expert. The prompt cache is reserved first, and the atlas is the RAM that sequence leaves. The mixer is scored in chunks of 2048. The expert multiply then runs once for the layer on the atlas images. An expert already resident is not read again. A routed expert, including a pin, is staged from the fp4 file when it is not already resident. A one-token decode runs the fp4 gate and down GEMV on the atlas. The host does not read the ten ids between layers. An id that belongs to another tier is not a miss. Prefill steps each layer's mixer in chunks of 2048 tokens and rewinds one scratch arena after each chunk, so that layer's hot and cold files are read once. That rewind waits for the open command buffer. The next chunk writes into the same bytes, and a host store would replace values those kernels have not read. On the n-gram layer, a longer prompt's page loads land in that arena and finish in the same wait. Those loads land in the scratch arena. A longer prompt applies the routed experts once after those chunks. That arena is 2 MiB per token in the chunk, or 256 MiB, whichever is larger. A scratch or cache allocation the device refuses raises. Decode keeps two arenas: the expert kernels and the residual write are committed after that layer, and the next layer encodes into the other arena while those kernels run. The prefill scratch is released before those arenas are allocated. The residual stays in its own buffer. RMSNorm, SiLU, sigmoid, softplus, L2 norm, RoPE, both depthwise convolutions, residual adds, the branch mean, and the router softmax and top-10 are shaders in that same command buffer. Hyper-connection norms are Gemma-style, `x / rms · (1 + w)`. The GDN head norm is the multiplicative form, `x / rms · w`, with the sigmoid output gate applied after it. Q and K are L2-normalized, and Q is then scaled by `1/√128`. The attention query projection splits into the query and a sigmoid gate. Activations stay in device buffers. The dependence is the embedding, then for each of the 48 layers a residual read, a mixer, a residual write, the router, the shared expert, and up to ten routed experts. Layer 1 adds the n-gram injection into the four residual branches before its mixer. The output head runs once on the last token of a prefill chunk. A decode span of two to four tokens runs it on every position. Decode then runs the resident MTP layer for one draft step at the request temperature. Drafts start whenever that layer is loaded. The previous span's expert ids are staged before those steps. A cycle that does not draft still steps the MTP layer, so its cache stays at the token count. Drafts stop for the rest of the request when the latest four cycles fall below half the best four-cycle rate. That step selects blocks. A longer draft limit reuses the selection for the later steps. One backbone forward consumes the span. The key and value store is ordered before that span's attend, and the two store phases are ordered so the completed block still reads the previous tail. Draft steps restore the MTP layer's unfinished tail before that forward. A partial accept restores the recurrent state after the kept prefix and carries the corrected token into the next span so that token is forwarded once. Four positions of that state, and the residual at each of those positions, are reserved before the atlas is sized. When the request ends on the corrected token, that token is forwarded before the prefix is stored. When those copies are absent, the kept prefix is forwarded again. A draft is kept with probability min(1, p/q) after temperature, top-p, and top-k, and a rejection draws the residual on the device. Temperature 0 keeps the draft when the argmax matches. Experts on that span are fp4 E2M1, read once per distinct id and reduced in the one-token slot order. The MTP cache is stored with the prefix. K and V default to E4M3 on each completed block of four, with an E8M0 scale every 32 channels, and the unfinished tail stays BF16. `--kv-cache bf16` stores every K and V token as BF16. The indexer key is BF16 in both modes. `serve`, `complete`, and `bf16` take that switch. The log reports the end-to-end rate and an after-load rate. End-to-end divides tokens by wall time, including the prefill file read and the atlas fill. Prefill's after-load rate divides the prompt tokens by GPU time, which starts once that command buffer's file wait has finished. Decode's after-load rate starts on the first step whose resident count does not grow, and reports that window's wall time and its GPU time. A prefix hit that steps nothing logs prefill as zero tokens. `complete`, `bf16`, and `serve` accept `--transcript`. That file receives the prompt and the completion. Token rates stay on the console.

The host commits a command buffer when the next load needs a value that buffer will produce. These steps stay on the host:

- The chat template and the tokenizer emit token ids. Those ids are copied into the buffer the embedding gather reads.
- The n-gram mix is sixteen wrapping int64 XORs of token ids the host already stores. Each result selects a 128-byte slot. A single token loads the 16 KB page that contains that slot through Metal IO into a small page cache, and a shader reconstructs the row. A chunk of at least 256 tokens computes those ids in one segment scan and expands every slot from the pages that chunk loads. That packed destination offset is a multiple of the 16 KB page. A prompt longer than one chunk finishes those loads in the rewind that follows the chunk. That rewind waits on every layer, because the next host write reuses the arena. The multipliers, head offsets, and vocabulary sizes are 280 bytes of int64 at the tail of `resident.bin`, copied out of that buffer once after it loads. The formula is in [ngram.md](ngram.md).
- The sampler keeps a top-k of at most 32 on 1024 threads, then draws from that list. Temperature 0 still uses the parallel argmax. The router shader writes ten expert ids and ten weights. One simdgroup owns one token. The host reads the ten ids, once per layer, on prefill and on a decode token whose experts are not yet known to be resident. The host reads the router ids for the chunk, stages any missing run into the atlas, and encodes the grouped kernels. On an untrusted decode token it stages any missing run before that layer's expert kernels. The previous token's ids for every layer are already in flight, so a hit does not read the file and a later layer's load overlaps this layer's mixer. The atlas is allocated on the first prefill, after that prompt's cache is reserved, and sized from the memory that sequence leaves. When a later suffix has grown the cache and the mapped atlas is more than 1 GiB above the budget for that length, that buffer is released and the next decode allocates the smaller one. That budget is the footprint from before the buffer was allocated, plus the cache added since. A fixed resident percent is left as requested. A later prompt keeps the atlas and stages only the experts that prompt routes to. `--resident-percent` requests that share of the hot-tier bytes and steps down by 4 GiB until 8 GiB. Omitting it sizes the atlas from the memory the live sequence leaves: physical memory, minus this process's footprint, 6 GiB of headroom, and room for one cache growth. A shorter sequence keeps a larger atlas. The budget is not larger than the hot and cold expert files together. A refused size steps down by 1 GiB, then by 4 GiB until 8 GiB. A sequence whose cache no longer fits grows the cache beside the atlas. When that allocation does not fit, victim runs are discarded and the atlas stays mapped. After a decode token whose routed experts were all resident, the next token leaves those ids on the device. The expert kernels run in the same command buffer as the mixer, and the host reads the ids once at the end of the token. A miss loads the missing experts and replays that token from the recurrent snapshot. The weights stay on the device. On the untrusted path that per-layer read ends the command buffer that produced the ids, and the expert kernels are committed with the residual write, without waiting, so the GPU runs them while the host encodes the next layer.
- Sampling returns one token id. Temperature at or below zero is a GPU argmax. A positive temperature builds the probability vector and walks the CDF on the GPU; the host passes in one uniform draw. A drafted token is accepted by a second kernel that builds the target and draft distributions the same way, keeps the draft when a uniform is below min(1, p/q), and otherwise draws the residual. The host reads that id. A presence penalty is subtracted once from each distinct token in the last `penalty_window` tokens. Omitting it leaves 0 while thinking is on and 1.5 when thinking is off. A frequency penalty is subtracted once for every copy in that window. Omitting frequency leaves 0. The window defaults to 20. A window of 0 uses the whole completion. The id is the stop check, the prefix-cache key, and the next step's token. While a function name is open, or a `tool_choice` names one function, the draw is limited to the tokens described in ARCHITECTURE.md.
- The converter packs on the host because that command writes the file the shaders read.
- `bf16` reads a shard row for an expert or an n-gram vector, uploads it, and then uses these shaders. `serve` and `complete` do not open those shards.

Missing decode ids are sorted, and each run of consecutive ids is one sequential load of `(last − first + 1) × live` bytes from file offset `first × live` into one resident atlas. The destination offset in that atlas is the same multiple of 16 KB. An int64 table stores each image base, and an empty entry is −1. The shader reads the live bytes at that base. The default victim is S3-FIFO: a one-hit run leaves the small FIFO before a reused run is dropped from the main FIFO. ``cold_lfu`` drops a cold run first, and LRU drops the oldest run. A run that intersects the ids being staged, or the previous token's predicted ids, stays. The IO queue is concurrent, and each IO buffer waits for the previous signal before its loads, so a later event value means the earlier loads have finished. An expert or n-gram load signals that shared event, and the compute command buffer waits on the value for the image it is about to read. A decode step submits the previous token's ids for every layer before the first mixer, and each layer waits only for its own signal, so later loads stay in flight while earlier layers run.

A resident hit on decode does not read the file. A streamed prompt call reads every hot and cold image in the layer, so its transfer size is those tier files. A short suffix of the live sequence reads an expert file only for an id the atlas does not already hold. Matrices loaded once are read at startup into one shared buffer. Their per-token path does not return to the SSD.

The router stays float16 and uses its own shader dot. The token embedding is one fp4 row, gathered and reconstructed. A query whose visible length fits in the dense attend kernel attends every token. A longer query scores each complete block of 4 indexer keys, the mean of the block then the sum of ReLU dots over the 4 query heads, and attends the top 512 blocks plus the unfinished tail. A decode query reduces that dot with a simd sum across the 128 channels, then adds the four simdgroup sums. A prefill chunk leaves each lane on its own query and adds that query's channels in order. The top 512 is one threadgroup per query: each thread owns a contiguous run of blocks, and the histogram and the index-ordered collect match the host radix, so a tie keeps the lower block index. The attend reads K and V from the cache: a completed E4M3 token is dequantized per 32 channels, and a BF16 token is expanded from the stored bits. The sparse attend takes that mode from a device word. A prompt is not refused for length. The cache grows with the sequence, and the atlas is what that sequence leaves free.
