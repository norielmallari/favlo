# Qwen3.8-Flash-Next

As-built contract for the `qwen38-flash-next` pipeline. The process, the listener, and which files an agent may edit are [../../ARCHITECTURE.md](../../ARCHITECTURE.md). That file wins on those points. This file wins for this pipeline's records, cache, prefix, and kernels. Another pipeline does not edit this tree.

Clients reach this pipeline through `favlo serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. Quantize, probe, matmul, kernels, bf16, and complete require `favlo --qwen38-flash-next`. That flag loads `qwen38-flash-next.py`, which loads the `qwen38_flash_next` package. The package does not import another pipeline.

The target machine is an M5 Pro: 20 shader cores, a neural accelerator beside the shader pipelines in each core, 307 GB/s unified DRAM, and an APFS volume whose device block and allocation block are 4096 bytes. Requires macOS 27 and the matching Metal SDK. The 16-core Neural Engine is not used. Sub-byte tensor planes also require 128-byte alignment inside the record. A 4 KB file offset does not by itself satisfy that.

Layouts are in [record.md](record.md). The n-gram hash is in [ngram.md](ngram.md). The kernel schedule is in [schedule.md](schedule.md). The recorded prefill and decode rates are in [performance.md](performance.md). The file-reading sum is a measurement in [research/recorded-forward.md](research/recorded-forward.md). The probe is in [probe.md](probe.md). The papers are in [references.md](references.md). Implementation plans are not in this tree. This file wins if one of those notes disagrees with it.

Registration copies `sampling.py` onto the registry row. The default variant is thinking. A benchmarks run that names this pipeline writes [benchmarks.md](benchmarks.md). `quantize` names the record directory from the expert widths in `formats.record_name`: wider quants first, `fp8`, `fp4`, then `int2`.

## In scope

- `qwen38_flash_next` runs three stages for this model: a BF16 calibration prefill, a converter from Hugging Face BF16 shards to native records, and the text runtime. `qwen38-flash-next.py` is the entry the command loads.
- One sequence at a time. Prefill and decode. Layered kernels.
- `GET /v1/models` and `POST /v1/chat/completions`, including streaming.
- The checkpoint chat template. Sampling is temperature, top-p, and top-k.
- Tool calls. The template renders `tools` and tool results. A completion that contains `<tool_call>` blocks is returned as OpenAI `tool_calls`, on the JSON response and as stream deltas. A request with `tool_choice` set to `none` leaves that text in the message content. While a function name is open, the sampler keeps only tokens that continue a name from that request. A `tool_choice` that names one function forces the opening `<tool_call><function=name>` before the arguments. Those opening tokens are the tokenizer's encoding of that text, so a later render of the same opening is the same ids. A function with no parameters forces the closing tags the same way. Generation stops when that call's `</tool_call>` has closed.
- A prefix cache so a continuation prefills only the new tokens.
- Expert streaming from SSD into a resident atlas. Consecutive expert ids are one sequential Metal IO. The shader reads the live image from that atlas.
- The harness scores IFEval, GSM8K, and HumanEval against `serve`. The checker reads `message.content`. Thinking stays off. Omitted sampling fields come from `GET /v1/models` row `<id>:instruct`. A harness flag overrides that field. The note is [benchmarks.md](benchmarks.md).
- The carrot smoke is [tests/test_smoke.py](../../tests/test_smoke.py). The stored completion is greedy instruct, written to `carrots.json`. The reply collects 6 carrots. The other cases use this pipeline's instruct and thinking cards. A reasoning effort runs only when this checkpoint's template names it.

## Out of scope

- A generic runner and any edit to `qwen38_flash_next` on behalf of another model.
- Affine group-64 packing and per-layer bit allocation.
- Batching and the Neural Engine.
- The vision tower. It stays unloaded.
- A tool-call grammar beyond the sampler mask. A draft the existing sampler would not emit is a mismatch.
- Fusing a whole layer into one kernel. The runtime is a layered loop. Shaders share a command buffer until the host needs an expert file offset or the sampled token id.
- Integer int8 and integer int4 as weight planes. The half × int8 `matmul2d` dispatch does not complete, so that format is not stored. Further key/value widths: fp8 E5M2, unscaled fp8, int8, int4, fp4, int2, and a wider K than V.
- A dependency on another inference app: its packages, its virtualenv, or its files. The README credit is a link, not a library.
- A second, slower forward. Host GEMV and CPU matmul of activations are not stand-ins for a missing shader. The converter's packing runs on the CPU because it writes the file. The request path does not.

## Qwen3.8-Flash-Next

48 layers, hidden 2560. Twelve repeats of three Gated DeltaNet layers and one Qwen Sparse Attention layer, each followed by MoE. The router is 512-wide, top 10, plus one shared expert. Expert intermediate size is 640. The token embedding and the output head are separate untied matrices, vocabulary 248320.

Gated DeltaNet is 36 layers and keeps a fixed 128×128 state per value head. Sparse attention is 12 layers: K and V for 2 heads of 256 channels, and a 128-channel indexer key per token. The indexer pools keys in blocks of 4, then picks up to 512 blocks (2048 tokens) plus the unfinished tail. MTP is one extra sparse-attention layer with its own 512 experts, resident in `mtp-experts.bin`. Decode always enters one cycle. That cycle runs the MTP layer for one draft step at the request temperature while drafts are enabled, and forwards the sampled token when they are not. Drafts start whenever that layer is loaded. The previous span's expert ids are staged before those steps. A cycle that does not draft still steps the MTP layer, so its cache stays at the token count. Drafts stop for the rest of the request when the latest four cycles fall below half the best four-cycle rate. That step selects blocks. A longer draft limit reuses the selection for the later steps. One backbone forward consumes the sampled token plus those drafts and returns a logit row per position. The key and value store is ordered before that span's attend. A draft is kept with probability \(\min(1, p/q)\) after temperature, top-p, and top-k; a rejection draws the residual on the device. Temperature 0 is that rule when \(p\) is a point mass on the argmax. The span expert dot is fp8 E4M3 or fp4 E2M1. A span of two to four tokens runs `gemv_int4_span`: each int4 weight is read once and dotted with every token in the span. The one-token projection stays the GEMV. A longer chunk uses matmul2d. An int2 expert in that span uses the grouped int2 shader. The fp8 and fp4 experts in the same span stay on the span kernels. A draft that keeps every guess writes the last guess into the MTP cache and leaves that cache in place. A draft that stops early restores the unfinished tail before the backbone forward. A partial accept restores the recurrent state after the kept prefix, including the unfinished key and value tail, and carries the corrected token into the next span so that token is forwarded once. Four positions of that state, and the residual at each of those positions, are reserved before the atlas is sized. When the request ends on the corrected token, that token is forwarded before the prefix is stored. When those copies are absent, the pre-span state is restored and the kept prefix is forwarded again. The MTP cache is stored and restored with the prefix. The accept length on this record is not published here. The schedule is [schedule.md](schedule.md).

The n-gram table is injected at decoder layer 1, before that layer's residual read. The hash, the branch gate, and the residual `1/n_r` read are in [ngram.md](ngram.md).

## Records

The directory this tree serves is record version 6. The shipped map is 48 rows of 512, every width 4. A record may also pack fp8 and int2. Each expert is stored once, in the file for its width, and expert id `e` in a uniform fp4 file starts at `e × stride` in `experts/NN-fp4.bin`. The manifest `super` list is the atlas pin: layer 2 expert 322, layer 4 experts 108 and 373, layer 6 expert 223, and layer 10 expert 107. Those images stay in the file for their width. The atlas loads them when it is created and does not evict them. A uniform fp4 record uses the fp4 matmul and GEMV for every expert, including the pins, and the one-token path leaves those ids on the device when that token loaded no expert image. A mixed record reads the ids on the host. fp8 uses `gemv_int8`, fp4 uses `moe_decode_gate` and `moe_decode_down`, and int2 uses the int2 decode kernels. `quantize` writes version 6 from `quant_map.json`. `--mtp-bits` defaults to fp4. Every plane uses an E8M0 scale every 32 values. `num_experts` stays 512. A version 5 directory name counts experts per file. That count is not a pad. Do not pad an expert count to a multiple of 32. The matmul tile of 32 is a kernel constraint, not a count constraint.

`quantize` is the only command that quantizes a weight. `serve` and `complete` read the record and do not open the BF16 shards.

Image sizes, the five super ids, the directory name, and the E8M0 rule are in [record.md](record.md). The int2 reconstruction bound is a measurement in [research/int2-miss.md](research/int2-miss.md).

## Firing

A chat completion counts the router ids the host already read. Prefill counts every uncached token. A decode span counts the tokens that stay, once. A request that stops mid-forward is stored with `complete` false and is not a score. The integers stay in memory until the request closes. The daemon then runs the lull. One SQLite transaction in `~/.favlo/telemetry/<folder>/firing.sqlite` writes them. A complete request also stores the cached token count, the finish time, the prefill and decode seconds, and how many experts were fp8, fp4, and int2. The lull writes those counters. When no process holds the record, it promotes one expert and demotes one. fp4 steps to fp8 at a relative score of 4 or more and to int2 at 0.25 or less. fp8 steps back to fp4 at 2 or less. int2 steps up to fp4 at 0.5 or more. One step at a time. Pins stay. The new image is quantized from the BF16 source. A rewrite of `manifest.json` changes the prefix id.

## Key/value cache

The shipped record is fp4 experts and an fp8 E4M3 key/value cache. A mixed record serves the width each expert was packed at. `serve`, `complete`, and `bf16` take `--kv-cache e4m3` or `--kv-cache bf16`. The default is `e4m3`.

E4M3 stores each completed block of four K and V tokens as `metal_fp8_e4m3` with an E8M0 scale every 32 channels along the head. The scale rounds up so the peak of the block fits in the finite E4M3 range, whose largest value is 448. The unfinished tail, at most three tokens, stays BF16. K and V for a completed token are 1,056 bytes, 12,672 bytes across the twelve layers.

`--kv-cache bf16` stores every K and V token as BF16, including the tail. That is 24,576 bytes per token across the twelve layers.

Indexer keys stay BF16 in both modes. At 262,144 tokens they add 0.75 GiB. The live prefix keeps the tail, and the next token of the same sequence reads it. Pooling is mean, then cast back, then norm, then rotary, in that order.

## Context

A prompt is not refused for length. The key/value cache grows with the sequence. Every prefill reserves that prompt's key/value cache, then allocates the atlas from the memory the sequence leaves. Its size is physical memory minus this process's footprint, 6 GiB of headroom, and room for one cache growth. A shorter sequence leaves a larger atlas. A longer sequence leaves a smaller one, and decode reloads more experts. When a later suffix has grown the cache and the mapped atlas is more than 1 GiB above the budget for that length, that buffer is released and the next decode allocates the smaller one. That budget is the footprint from before the buffer was allocated, plus the cache added since. A fixed resident percent is left as requested. The atlas is not larger than the hot and cold expert files together. If the device refuses that size, the next try is 1 GiB smaller and later tries step down by 4 GiB until 8 GiB. A sequence whose cache no longer fits grows the cache beside the atlas. When that allocation does not fit, the atlas discards victim runs and stays mapped.

`serve` and `complete` take `--resident-percent`. That is a fixed atlas budget, a percent of the hot-tier bytes, page-aligned, stepping down by 4 GiB until 8 GiB or the device accepts the buffer. Omitting it sizes the atlas from the live sequence instead. The indexer attends at most 512 blocks of 4, plus the unfinished tail.

The indexer attends at most 512 complete blocks of 4 tokens, plus the unfinished tail. A visible span that fits in the dense attend kernel attends every token. 2048 is that attended window, not a cap on the prompt.

## Prefix cache

One request at a time. The process keeps one live sequence. A hit is an exact token prefix of that sequence, after the checkpoint template has been applied. The usual hit is the previous turn of the same chat. The stored length is the real token count, including an unfinished E4M3 tail. A request that extends the live sequence prefills the suffix. That prefill writes the longer token list when it finishes. A suffix of the live sequence keeps the resident atlas and stages only the experts that suffix routes to.

A completed prefill writes that token list before decode starts and leaves the expert atlas mapped. A client that closes the socket writes the live sequence before the request returns when decode has extended it. A draft span that is in the cache and not yet in the token list is rewound to that committed length before the prefix is written. The verify forward of a draft that already stepped the MTP layer keeps that cache and commits it with the span. SIGINT and SIGTERM do the same before the device is released. A forward that stops in the middle restores the snapshot taken before that forward, then writes that earlier boundary. The sequence stays in memory after a client disconnect, so a later request in the same process can still extend it. A later process loads the file.

Any other request writes the live sequence, clears it, and loads the longest stored token list that is a prefix of the new prompt. The suffix is what gets prefilled. A shared system prompt hits when some earlier request stored a boundary at that prompt. A boundary that was never stored is not implied by a longer file. An exact-length hit samples from the stored logits. A file with no logits is prefilled again.

The bytes are the shared prefix record in `src/favlo/prefix.py`. The directory is `~/.favlo/prefix/qwen38-flash-next/<checkpoint>/<hash>.bin`. The checkpoint id is the hex SHA-256 of `manifest.json`, or of `config.json` when the record has no manifest. The tag is the active key/value mode, `e4m3` or `bf16`. A file whose header hash, model, digest, or tag does not match is ignored. An exact-length file is used only when its `logits` region holds one vocabulary vector. A file with an empty `logits` region is a prefix for a longer prompt and is prefilled again when the prompt is the same length.

Each file stores, at that boundary:

- the token ids
- `attn.{layer}.key`, `attn.{layer}.value`, `attn.{layer}.key_tail`, `attn.{layer}.value_tail`, and `attn.{layer}.indexer` for every cached layer
- `gdn.{layer}`, the Gated DeltaNet recurrent state once, not once per token
- `conv.{layer}`, the Gated DeltaNet depthwise convolution history (kernel 4), once
- `ple`, the n-gram convolution state, once
- `logits`, the last vocabulary vector, or empty when that boundary has no distribution

Grammar state is not stored. It starts again on the new generation. Expert images stay in the weight record.

Regions that Metal reads start on a 16 KB page. A load larger than 256 MB is split into 256 MB pieces. The write goes to a temporary name in the same directory and replaces the destination after the header hash is in place. A crash leaves the previous complete file. When the new token list extends a file already in the directory, a region whose stored bytes are a prefix of the new blob is copied forward and the new tail is written after it. A region that does not match is written from the live buffer. The shorter file stays until eviction.

The partition for one model and one checkpoint is kept to 32 GiB. Past that, the oldest files are deleted. The file just written stays. Replacing the live sequence keeps the mapped experts. A prefix write leaves the atlas mapped. Stopping the process drops the device, and the atlas with it. A volume that refuses the write is logged, and the new request still runs; the boundary that could not be written is not stored. When RAM is short, drop the live prefix before the resident expert tiers. A short prefix can be cheaper to prefill again than a cold expert read.

## Endpoint

`favlo serve` listens on `127.0.0.1:8129` with nothing loaded. A request names a folder or an alias from `models/registry.json`. A pipeline name names a row when exactly one registered record uses that pipeline. The same pipeline and the same folder stay resident. A different folder or a different pipeline unloads the previous record and loads the one named. `GET /v1/models` lists every registered pipeline: each folder, its alias, and the `:thinking` and `:instruct` rows. An empty registry lists no models. A variant is a sampling row on that record, not a second record. The registry row stores `context_length` 131072 and `max_prompt_tokens` 131072 for this pipeline. `GET /v1/models` includes both fields on this pipeline's rows. A completion and the usage chunk before `[DONE]` include `context_length`, `prompt_tokens_details.cached_tokens`, and `max_prompt_tokens`. The final usage object, on a non-streaming response and on that chunk, includes `timings`: `prompt_per_second`, `predicted_per_second`, `prompt_n`, and `predicted_n`. `prompt_tokens` stays the full prompt. `prompt_n` excludes the cached prefix. `complete`, `bf16`, `quantize`, `probe`, `matmul`, and `kernels` stay under `favlo --qwen38-flash-next`. The listener is `GET /v1/models` and `POST /v1/chat/completions`, including a streaming response. The process serves one request at a time. A connection that arrives while a request is open waits in the listen queue until that request has returned, including its error response. A client that closes the socket ends that request, including during prefill. The server closes its side of the connection. A stream write that cannot complete within 2 seconds ends the request the same way. A client that closes before that response is written does not print a traceback. SIGINT and SIGTERM stop the process. The listening socket is closed, the GPU work is finished, and the Metal device, the expert atlas, and the record files are released. The decode loop enqueues each sampled id and continues to the next step. Once a decode token's routed experts were resident, the next token leaves the ids on the device and reads them once at the end of the token. A miss loads the missing experts and replays the token. A side thread detokenizes those ids and writes the events. The console line for a request is the prompt token count, the cache hit, the incoming token count, the prefill rate, the output token count, and the decode rate. The incoming count is the prompt length minus the cached prefix. A cached length of zero is a miss. A trailing replacement character stays buffered until the next token resolves it or the stream ends. Tokens inside the open think block stream as `reasoning_content`. Tokens after `</think>` stream as `content`. Messages are tokenized with the checkpoint chat template. `continue_final_message` leaves the last assistant message open and generation continues that text. A request may carry `tools`, and the template renders them. The sampler applies temperature, top-p, and top-k. A request may set `presence_penalty` or `frequency_penalty`, and `penalty_window`. Presence is subtracted once from the logit of each distinct token in that window. Frequency is subtracted once for every copy in the same window. The window defaults to the last 20 tokens. A window of 0 uses the whole completion. Omitting presence leaves it at 0 while thinking is on, and at 1.5 when `enable_thinking` is false. Omitting frequency leaves it at 0. An explicit value is kept, including 0. A request that omits a field uses the Qwen3.8-Flash-Next model card for the active mode. Thinking, used when `enable_thinking` is omitted or true, is temperature 1.0, top-p 0.95, top-k 20. Instruct, when `enable_thinking` is false, is temperature 0.7, top-p 0.8, top-k 20. A field the request sets is kept. Temperature 0 is an argmax. `complete` and `bf16` follow the same rule from `--thinking`. Generation stops on the tokenizer end-of-turn id and on the text-config eos. A request that sets `max_tokens` or `max_completion_tokens` stops after that many tokens. An omission leaves the output uncapped. The n-gram segment boundary stays the text-config eos. A completion that contains `<tool_call>` blocks is returned with `finish_reason` `tool_calls`. A request with `tool_choice` set to `none` keeps that text in `message.content` and finishes with `stop`. While the function name is still open, the next token has to continue one of the names in `tools`. A `tool_choice` that names one function forces that call's opening before the arguments are sampled. The parameter text is not masked. A request that omits `enable_thinking` leaves `<think>` open, so decode writes the reasoning. Setting it false closes that block in the prompt. `reasoning_effort` is forwarded to the template. Omitted, or `none`, the template uses xhigh while thinking is on. The accepted values are xhigh, medium, and low. Tool results on the next turn are `role: tool` messages, and the cache key is the token ids the template actually emitted. The server keeps one stepped prefix in memory. A request whose ids extend that prefix continues. Any other request writes the live prefix under `~/.favlo/prefix` and loads the longest stored prefix of the new ids before stepping the suffix. A completed prefill writes that prefix under `~/.favlo/prefix` before decode starts, so a later process can load it without waiting for the client to disconnect or the process to stop. Closing the client, and shutting the process down, write the sequence again when decode has extended it.

The checkpoint's tool-call syntax is `<tool_call><function=name><parameter=name>value</parameter></function></tool_call>`. The JSON response includes `created` as unix seconds and puts those calls on `message.tool_calls` with the arguments as a JSON object string. A streaming response emits the text before the call as content, then one `tool_calls` delta per call. Text with no call stays `message.content`. A request with `tool_choice` set to `none` streams the call as content and does not emit `tool_calls`.

## Calibration

The profiler does not quantize a weight. It runs this app's BF16 prefill. The default collect is 128 sequences of 512 tokens, drawn from prompt strings in a bucket JSON (`tool_calling`, `chat`, `mixed`, `reasoning`, `code`, `en`, `ko`, `zh`, `ja`). That file is prompt text. The citations are [REFERENCES.md](../../REFERENCES.md).

Only the strings matter. A later corpus file can use another layout. `tool_calling` and `chat` are already wrapped in `<|im_start|>` turns, so those strings are tokenized as they stand. The other buckets are raw text. The activation file is rebuilt when the strings or the tokenizer change.

For each routed expert it records how many tokens selected it, the input energy to `gate_up` along K = 2560, and the input energy to `down_proj` along K = 640. An expert only accumulates tokens that routed to it. Each dense projection stores one energy vector. The router, the n-gram table, and the key/value cache are not in the file. Tier lists are copied from selection so a hot block cannot promote a narrow expert.

The collect signature is the corpus hash, the sample count, the sequence length, and the tier assignment. Resume is per sequence.

## Schedule

Prefill and decode are Metal shaders. A missing kernel stays missing. Every prefill, including a cold prompt and a long one, loads each miss into the atlas. One expert selected by several tokens is marked reused, and S3-FIFO keeps it; a one-hit stays in the small FIFO. The mixer is scored in chunks of 2048. After a layer's chunks, the experts that layer routed are loaded into the atlas. An expert selected by at least 64 tokens is applied with `matmul2d` on that resident image, for the whole layer. A smaller group stays on the grouped shader, which reads the same atlas. An expert already resident is not read again. Atlas bytes that do not hold a live expert image are reusable. macOS may discard those pages; they are not kept as swap. A span is committed when an expert image is loaded into it. The default victim is S3-FIFO: a run seen once sits in a FIFO of one tenth of the atlas and leaves before a run that has been requested again. That second request stays in the main FIFO. ``cold_lfu`` drops a cold run before any hot run, and LRU drops the oldest run. A protected run, the ids being loaded and the previous token's predicted ids, is not a victim. The pager is not the stream: a miss still reads the expert file with Metal IO. Decode of one token is the fp8 or fp4 GEMV on the atlas image. Decode stages missing expert runs. Scratch for a prompt chunk is 2 MiB per token, or 256 MiB, whichever is larger. Prefill has one arena. Rewinding it waits for the open command buffer, so the next chunk's host writes do not replace bytes the previous kernels still read. On the n-gram layer those writes include the page loads for that chunk. The half × int8 `matmul2d` dispatch does not complete on this GPU, so it is not on the request path.

The kernel map, the quantize workers, and the host steps are in [schedule.md](schedule.md). Kernel and bandwidth ceilings for these kernels are in [ceilings.md](ceilings.md). The isolated dispatch sum is a measurement in [research/kernel-ceilings.md](research/kernel-ceilings.md).

## Probe

`favlo --qwen38-flash-next probe` measures one block of 32 on this GPU before an expert table is packed. Nibble order and the int4 endpoints are in [probe.md](probe.md). `matmul` checks one fp4 E2M1 tile and one fp8 E4M3 tile through `matmul2d`, and the fp4 tile through the decode shader dot. It does not load the checkpoint.

## Build order

1. The block-of-32 probe is the int4 measurement. int2 element order against Apple's `unpack` is still open.
2. The profiler writes the activation file from this app's BF16 Metal prefill. The prompt strings come from that bucket JSON.
3. The converter writes the native records with the E8M0 rule in [record.md](record.md). Packing is the host writing the file the shaders read.
4. `serve` steps the shaders in [schedule.md](schedule.md) and returns those tokens from `POST /v1/chat/completions`. A second request that extends the stepped prefix does not repeat that span. Hidden-state error against a BF16 prefill is not measured yet.
