# Wan 2.2 I2V

Four-step image-to-video pipeline for [Wan-AI/Wan2.2-I2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-I2V-A14B). `favlo --wan22-i2v` loads `pipelines/metal41/wan22-i2v.py`. The high-noise expert runs while the timestep is at least 900. The low-noise expert runs after that. One expert is on device at a time. Device spans come from the process memory manager. The listener passes `owner` and `max_memory`, and `close` sweeps that owner. One diffusion step keeps every requested frame resident with one expert. The decode keeps every frame on device when the remainder covers that volume, and otherwise one latent frame. The clip length and the resolution stay the request. A shortfall raises before the first commit and again at each stage boundary when the ledger no longer covers that stage. The VAE drops its device weights after encode and after decode; host checkpoint bytes load only for encode and decode. After each expert upload, host quant arrays are dropped and only device spans stay resident. The ledger room for decode is read after the device finishes in-flight work so a inflated ``pending`` count does not force one latent frame when the full volume fits. The expert and the DiT scratch are released before decode. The expert and the scratch spans are released when the clip finishes and when a step fails. `matmul2d` consumes fp4 E2M1 or fp8 E4M3 weights with an E8M0 scale. The left operand is float16 and the destination is float32. A row whose peak exceeds 60000 is divided by that peak over 60000 before the half store, and the product is multiplied back. Biases, QK RMSNorm, `norm3`, modulation, and the patch convolution stay float16. Those weights are under the Apache License, Version 2.0. The text encoder is [google/umt5-xxl](https://huggingface.co/google/umt5-xxl), also Apache License 2.0.

`setup` writes each download under `models/<org>/<repo>/`. The VAE is `models/Wan-AI/Wan2.2-I2V-A14B/Wan2.1_VAE.pth`. The umT5 encoder and tokenizer are `models/google/umt5-xxl/`, and a later encoder replaces that directory. The two expert safetensors are a separate repository directory, and `setup` prints their paths. Sixteen connections write one file. A short file continues from the ranges already on disk. `quantize` reads those two expert files and writes `models/Wan2.2-I2V-A14B-fp4`. It scores every block by the maximum fp4 relative error of its eight attention matrices and its two feed-forward matrices, after one K permutation per matrix. Twenty percent of the blocks, eight of forty, are stored as fp8. An equal score keeps the lower block index. The high-noise fp8 blocks are 15, 16, 17, 18, 19, 20, 24, and 26. The low-noise fp8 blocks are 11, 12, 15, 17, 18, 21, 24, and 26. Those lists are [research/block-fp4-error.md](research/block-fp4-error.md). Text, time, and the head stay fp4. `kernels` dispatches a 64 by 32 fp4 matmul and the same tile as fp8. `generate` writes an uncompressed 24-bit AVI. Rows are bottom-up BGR.

```text
uv run favlo --wan22-i2v setup
uv run favlo --wan22-i2v quantize --high <high.safetensors> --low <low.safetensors>
uv run favlo --wan22-i2v kernels
uv run favlo --wan22-i2v generate --record models/Wan2.2-I2V-A14B-fp4 --image still.png --prompt "The horse gallops at speed, its raised foreleg driving down and the trailing legs swinging forward into the next stride, mane and tail whipping. Fixed camera." --frames 5 --width 576 --height 320 --out clip.avi
```

The solver is four Euler steps with shift 5. The knots are 1000, 937.5, 833.3333, 625, and 0. The update adds `(sigma_next - sigma)` times the velocity. Frame count is `4n+1`. The shortest moving clip is 5 frames. At 16 fps, 81 frames is the 5 second clip. 320p is 576×320. 240p is 416×240. Both edges are multiples of 16.

The image is the first pixel frame. A still that is not the clip size is resized to that size. The other frames are zeros. `Wan2.1_VAE.pth` is the causal encoder and decoder: base width 96, multipliers 1, 2, 4, 4, two residual blocks, temporal downsample on the last two stages, latent width 16. Spatial stride is 8 and temporal stride is 4. The first frame changes in space only. The first encoded chunk skips the temporal convolution, and the next chunk's first temporal upsample does not read that frame. The latent the DiT sees is `(μ − mean) / std` with the published 16-channel vectors. The decoder inverts that affine and clamps to `[−1, 1]`. The four mask channels are 1 on the first latent time and 0 after that. The DiT input is 16 noise channels, the four mask channels, then the 16-channel latent. The head's 64 outputs are one time patch, a 2×2 spatial patch, then the 16 latent channels. Without that file, each 4×8×8 cell is averaged into the latent and the decoder repeats each cell. The text context is the umT5 encoder in `models/google/umt5-xxl/models_t5_umt5-xxl-enc-bf16.pth`, tokenized with `tokenizer.json` in that directory. Each layer's linears are half `matmul2d`, and the RMSNorm, gated GELU, residual, and bucket-biased attention are Metal kernels. The token rows are read from the checkpoint. The real tokens, including the end token, are padded with zeros to 512. Without those files the context is zeros. The DiT text MLP still runs. The VAE uploads weights only while encode or decode runs. A convolution of at least 32 output channels, 1024 outputs, and 64 taps is an im2col tile and a half `matmul2d`. Smaller convolutions stay on the float `conv3d` kernel. The encoder and decoder commit once per block, and each DiT block commits before the next one is recorded. The 1×1 projections, the channel RMS, the clipped SiLU, and both mid-block attentions are kernels, and the causal cache is a device buffer. The Euler step adds the velocity on device. The host sees the latent again at the decoder, then reads the uint8 frames for the AVI. Kernel and bandwidth ceilings for one 9-frame 576×320 clip are in [ceilings.md](ceilings.md). The isolated sum is a measurement in [research/clip-ceiling.md](research/clip-ceiling.md). A 9-frame smoke printed 41.06 s.

`favlo serve` answers `generate_video` on `POST /mcp` when the row defines `handle_video`. The response is a video job. A path under `/v1/videos` is 404. `progress` counts finished layers: each text layer, each packed weight as it is read and as it is uploaded, each shader pipeline, each DiT layer, and each VAE block. It is not a fraction of the elapsed time. It stays below 100 while `status` is `in_progress`, and it is 100 when the MP4 is stored. `stage` names the part in progress. `eta` is the remaining seconds from the finished-layer rate, and 0 when the job is completed. `serve` opens a `sample` row for the same count. The size, frame count, and duration are logged once when that row opens. The row then names the stage, and the console shows the ETA. Each Euler step also logs its seconds. `resources/read` of `favlo://videos/{id}.mp4` reads `~/.favlo/videos/<id>.mp4`. That MP4 is encoded from the uncompressed `<id>.avi` beside it. Both stay until `video_ttl_seconds` in `~/.favlo/settings.json`. The default is one day. `prompt` is required. `generate_video` passes the still as `image`: an id starting with `image_` from `generate_image`, resolved to PNG bytes before the handler runs, or a PNG block `{"type": "image", "data": "<base64>"}`. A filesystem path and a `favlo://` URI are refused. The handler also accepts `input_reference`. `size` defaults to `576x320`. `frames` defaults to 81. `seconds` snaps to the nearest `4n+1` frame count at 16 fps when `frames` is omitted. `quality` accepts `auto`, `low`, `medium`, `high`, `xhigh`, `max`, `standard`, and `hd`. The job reports `low`, `medium`, `high`, `xhigh`, or `max`. `auto`, `standard`, and `hd` are reported as `high`. An omission is `high`. The MP4 is `libx264` at CRF 32, 28, 23, 18, or 14 for those five reported levels. The MP4 stored for the job uses that reported level. `resources/read` returns that file. There is no later call that re-encodes another level. `seed` defaults to 0. A chat completion on this row is rejected. The message still names `POST /v1/videos`. A chat that arrives while this clip holds the GPU sets `state["preempt"]`. Cancel of the running task sets `state["cancel"]`. Both are `threading.Event`s. `generate` finishes the Metal dispatch already submitted, then stops. The boundaries are after compile, after the text context, after the VAE encode, between expert weight files, after each Euler step, after the VAE decode, and after the AVI is packed. A stop during the expert load keeps that step index. The resume reloads the expert and continues the same step. The device is closed before the waiting chat loads its model. The text table, the noise, the condition latent, the mask, the decoded frames, and the AVI bytes stay on `state["video_hold"]` with the same job id. The listener runs the waiting chats and calls `handle_video` again with the same body. That call keeps the id and skips a stage whose host outputs are kept. Compile and the resident expert are opened again, and layer counts already finished are not added a second time. Cancel leaves the job `in_progress` and does not keep the hold. The listener deletes a stored AVI and MP4 for that id.

## Smoke

`uv run pytest tests/test_wan22_i2v_smoke.py -s` dispatches both matmul tiles. `uv run favlo --wan22-i2v kernels` is the same check. `WAN22_SMOKE=1 uv run pytest tests/test_wan22_i2v_smoke.py -s` also generates 9 frames at 576×320 from `models/Wan2.2-I2V-A14B-fp4`. The step lines are the seconds printed by `generate`. ffmpeg writes `artifacts/wan22-i2v-smoke.mp4`. `python -m harness.video_smoke_agent` uses `qwen36-35b-a3b:instruct`. It draws the still with `Z-Image-Turbo-fp4` when `artifacts/video-smoke-agent.png` is missing or is not the clip size. The still sentence is the `prompt` in `smoke.json`, at that file's width and height. The clip sentence is `video_prompt`: the motion and a fixed camera. The still already defines the horse. It asks for the 9-frame 320p clip. `generate_video` reads `favlo://videos/{id}.mp4` into `artifacts/video-smoke-agent.mp4`. The same model then reads frame 0, the middle frame, and the last frame of that file and must affirm the still sentence. `python -m harness.video_quality_agent` draws a 416×240 still, then calls `generate_video` twice, at `quality` `low` and then `max`, with no chat between those tasks. Those clips are `artifacts/video-quality-low.mp4` and `artifacts/video-quality-max.mp4`. Exit 0 means both files are 5 frames at 416×240 and the max file is larger. Those commands are not part of pytest.
