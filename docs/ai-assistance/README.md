# AI-assisted features

These are the behaviors on `favlo serve` where a model writes or decides. Pipeline math, kernels, and quantize stay in that pipeline's note. A change to a feature on this page updates this folder in the same change.

The guides the configuration tools read are [../guides](../guides). The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). The listener is [../serve.md](../serve.md).

## Voice

The voice is a small horse who likes carrots. Favlo web stores that persona on the agent named Favlo. The configuration tool group adds the guide, setup, model, and download-reminder tools. Favlo web enables that group from an agent's details, and the Favlo agent has it on. The API note is [../../web-api/README.md](../../web-api/README.md). The app note is [../../web-spa/README.md](../../web-spa/README.md).

## Chat context

A chat completion reports `max_prompt_tokens`. The web agent stores that cap from the completion. When the prompt is at least half of the cap, older messages are left out of the next turn.

## Setup guides

`config_read_setup` returns `docs/<pipeline>/SETUP.md`. The argument is the pipeline id, the same stem as `favlo --<pipeline>`. `qwen35-4b` is Qwen3.5-4B. `qwen36-35b-a3b` is Qwen3.6-35B-A3B. `gemma4-26b-a4b` is Gemma 4 26B-A4B. `qwen38-27b` is Qwen3.8-27B. `z-image-turbo` is Z-Image-Turbo. `wan22-i2v` is Wan 2.2 I2V. `ace-step-15-turbo` is ACE-Step. The chat calls it when someone wants to set up, download, quantize, or delete that model. A pipeline with no setup page is an error that names the pipelines that have one. The page is not part of the standing instructions. It is loaded when the chat asks for it.

## Setup commands

`config_run_setup` runs one command from that page. The working directory is the checkout where Favlo is installed. `FAVLO_ROOT` is that directory. The command is not a shell: there is no `cd`, no pipe, and a path has to stay inside the checkout. It accepts `uv sync --extra dev` and `uv run favlo --<pipeline>` with `setup`, `quantize`, `quantize-text`, `delete`, `download`, or `models`, and the flags those setup pages use. `setup`, `quantize`, `quantize-text`, `delete`, and `download` close the resident model first. `serve` is not one of these commands.

## Registered models

`config_list_models` reads `models/registry.json` and returns one line per record: the folder, the pipeline, the alias, the key/value mode, and whether MTP is on with its draft depth. An unregistered complete record is named on its own line. An empty registry returns `no models are registered`. The chat calls this when someone asks which models are registered. `config_set_model_mtp` stores `mtp` and `mtp_depth` on that row. The next completion uses the row when the request omits those fields. A request field still wins. A row that omits `mtp` does not draft. A row that omits `mtp_depth` uses 3. Download and quantize stay in the models guide.

## Gallery tools

The curated gallery workspace is generative UI on the shared shell. Creating one captions every image with the workspace agent's model, listing every visible human anatomical feature, (the Providers default when that agent has no model), then the opening placement puts every image on the filmstrip and selects the first. The strip shows the image. The sidecar caption stays in the placement. That call uses the same clamps as `workspace_place` (60 images, unique paths, 80-character captions). Find and search list path and kind only; the agent calls `gallery_get_metadata` or `gallery_load_image` when it needs more. A selection change writes a durable fenced host cue (`<system_reminder>`, UI-hidden via AG-UI metadata) with the path and vision description into the thread snapshot once; the typed user text stays clean and prior cues stay until clear. The greeting is that same host-cue channel plus one assistant reply and does not call tools. A coding workspace only greets. Gallery folder tools are eager. Completed AG-UI turns keep loaded MCP remotes until clear so the tool schema stays a stable prefix. The gallery stays provisioning until every image has a caption. A failure after that still finishes provisioning and the chat shows it. A new gallery starts on Rosé Pine. The gallery page can use Favlo, Rosé Pine, or Catppuccin. Each scheme has a light and a dark palette and follows the shared Appearance preference. `gallery_set_theme` sets the same value. As-built detail (shell, catalog, tools, index, evidence) lives in the closed tree: `favlo-cloud/docs/maf/curated-gallery.md`.

## Skills

A skill is a name, a description, and a definition. Configuration stores a catalog of global skills. A global skill is not added to a prompt until it is copied. Add to new agents copies that skill onto an agent created later. Skills in `skills-global` follow the [Agent Skills](https://agentskills.io/specification) file: one directory, `SKILL.md`, YAML frontmatter for `name` and `description`, and the Markdown body as the definition. They are seeded into the catalog with that switch on, and onto the Favlo agent. `session-remember` uses `remember`, `recall`, and `forget`. Copy places the name, description, and definition on an agent or a workspace. The copy has its own revision, and a later edit or delete of the global skill leaves the copy. A turn appends the copies that apply as one markdown block: `# Skills`, then each skill as `##` plus its name, then the description, then the definition. A skill with no definition injects its description, which is the whole skill. Agent skills come first. An empty list adds no heading. The home channel receives that agent's skills. A workspace session receives that agent's skills and the workspace skills. The API note is [../../web-api/README.md](../../web-api/README.md). The app note is [../../web-spa/README.md](../../web-spa/README.md).

## Chat turns

A browser turn posts to `POST /ag-ui`, the Agent Framework AG-UI endpoint, and streams AG-UI SSE events. Heartbeats and gallery greetings call that same host. The thread snapshot is the chat record. Reasoning events are the thinking row. Tool-call events stay off the transcript unless that agent shows tools. Idle gaps use the same MAF transport keepalive (`sse-starlette` `: keepalive` comments every 15 seconds). The runner freezes the system prompt, tools, and model for that chat GUID until clear or a new chat. Editing a skill, tool group, MCP server, or model does not change an open chat until that chat is cleared. Compaction percent is read live from the agent (and workspace override), not frozen. An agent with no `default_model_id` uses the Configuration → Providers default model. A heartbeat run uses that owning agent's model the same way: the agent's provider and model when set, otherwise the Providers default. Each heartbeat run re-reads that choice (it does not keep a frozen listener id from an earlier beat). The agent's model settings may set `reasoning_effort`, `preserve_thinking`, and `expand_thinking` and `expand_tools` (`hidden`, `collapsed`, `running`, or `always`). Omitted thinking stays collapsed. Omitted tool calls stay hidden, so that block is left out and the activity chip says Working. `hidden` does the same for whichever block it is set on. Providers may set `reasoning_effort` too. The agent value wins. Not set on both leaves that field off the request. A set effort becomes `reasoning.effort` on that request. Thinking follows that field, else the selected model's registry `enable_thinking`, not the `:thinking` / `:instruct` sampling suffix. A legacy `enable_thinking` value still maps when effort is unset. `preserve_thinking` stays on the body. Qwen3.6 then keeps historical reasoning, so the next prompt extends the stored prefix. Each chat turn sets `store` true. The thread keeps the latest response id, and the next model call sends it as `previous_response_id` with only the new turn. The listener prepends the stored chain, including the reasoning item, before the pipeline renders the prompt. A missing id starts a new chain. The listener returns `content`, `tool_calls`, and `reasoning_content`. The API stores that reply, that reasoning, and each tool call. After `workspace_place`, the stream emits `STATE_SNAPSHOT`. The browser shows each call in its own row, in the order thinking, tool calls, and the reply arrived. Thinking closes when a tool call or the reply starts, and a tool call closes when thinking or the reply starts. A reply with reasoning and no text still finishes the turn. Stop posts `POST /sessions/{id}/cancel` (every running turn on that chat) before aborting the SSE fetch, so the Agent Framework stream and chat client close. A dropped SSE connection also sets that cancel event. Cancel marks those runs cancelled even when the stream is already gone, so a later turn is not blocked by a leftover running row.

## Session commands

The composer accepts two exact commands. `/session clear` deletes the messages, the runs, and the stored Agent Framework session for that chat GUID, mints a new chat GUID for the same slot, and returns the new id on the clear route. `/session archive` does not store the command as a chat message. It arms a run, then posts to `/ag-ui` with `forwardedProps.favloArchive` so the wrap-up streams without a user bubble. An empty `messages` list without that flag only reloads the snapshot. When that turn finishes, the same slot is cleared and a new chat GUID is minted. That completion status is `archived`, so the browser does not reload the retired session. A failed or cancelled archive leaves the GUID, the snapshot, and the MAF session. A channel command does not change a workspace chat, and a workspace command does not change the channel or any other workspace. The open chat drops its transcript when clear or archive completes. A `session.cleared` event on the new GUID is the birth of that chat. The browser clears the open transcript only when that event names the GUID still on screen as `previous_session_id`, so a remount that replays the birth event does not wipe messages written after the clear.

## Conversation tools

Favlo web enables Conversation tools from an agent's details. The switch starts off. The eager tool is `conversation_load_tools`. That loader adds `conversation_list_conversations`, `conversation_search_messages`, and `conversation_read_recent_messages` for the turn. List names the stored agent sessions, channels, and workspace chats. Search matches message text and returns a short snippet with the conversation id. Read returns the latest messages from that conversation, oldest first. The read count is capped at 50 and the search count at 20. While the switch is on, the tools read every one of those conversations. Heartbeats and configuration use the same pattern: `heartbeat_load_tools` and `config_load_tools` before their cold tools.

## MCP media

Favlo web connects an agent to an MCP server from that agent's details. The MCP section holds the global catalog; Add to new agents copies a catalog server onto an agent created later. A new agent starts with each default catalog server, including Favlo media pointed at the listener. The transport is HTTP or stdio. Test connection calls `tools/list` on MCP `2026-07-28`. The catalog stays in the API process and is not stored in a table. On a turn, each enabled server is passed to the agent as an Agent Framework MCP server with progressive disclosure. Eager remotes are image list/set/generate, memory (`remember` / `recall` / `forget`), and `media_status` / `media_cancel` / `read_media`. Video, music, and voice stay in `allowed_tools` when their groups are on, and the model loads them with that server's `load_tool`. Session column `loaded_mcp` keeps those remotes until `/session clear`. Each tool name starts with the server name, then the catalog name. `remember`, `recall`, and `forget` receive this agent as `client`. A generate call stays in the turn until `Client.call_tool` returns the tool result. The reply includes each `favlo://` link and leaves out the JSON. Those generate tools use the registry default for that media type. To change a model, the turn calls the matching list tool, then `set_image_model`, `set_video_i2v_model`, `set_video_t2v_model`, `set_music_model`, or `set_voice_model`, and repeats the returned session id in the reply. A later generate call passes that id as `session`. An omitted `session` uses the registry default. A failed result tells the turn to call the matching list and set tools and retry the generate tool with that session. The accepting turn tells the user that file is being generated. A disabled server or a disabled tool group is left out of the next turn. A turn enters an MCP client for each enabled server, with `io.modelcontextprotocol/tasks`, and passes that client to the framework tool. The client negotiates MCP `2026-07-28`. `Client.call_tool` resolves a task result before the tool call returns, and that result is the tool result in the same AG-UI run. Tool results use compact JSON (`dumps_for_model`) that drops empty fields.

## Shared memory

`POST /mcp` lists `remember`, `recall`, and `forget`. They read and write `~/.favlo/memory.db`. A recall ranks stored sentences with the BGE-M3 dense vector from `POST /v1/embeddings`. Hermes and other MCP clients call the same three tools on the listener. Favlo web can enable that group on an agent. A turn from that agent stores, searches, and deletes only the sentences kept for that agent. The store is not injected into anyone's prompt.
