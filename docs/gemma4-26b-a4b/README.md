# Gemma 4 26B-A4B

As-built note for the `gemma4-26b-a4b` pipeline. The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

`handle_chat` is a `LanguagePipeline`. The completion, the sampler, and the stream stay in this package. Clients reach this pipeline through `favlo serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `plan`, `quantize`, `kernels`, and `complete` require `favlo --gemma4-26b-a4b`. That flag loads `pipelines/metal41/gemma4-26b-a4b.py`, which loads `gemma4_26b_a4b`.

The official checkpoint is [google/gemma-4-26B-A4B-it](https://huggingface.co/google/gemma-4-26B-A4B-it). Those weights are under the [Apache License, Version 2.0](https://ai.google.dev/gemma/docs/gemma_4_license). `quantize` does not download. With no `--src` it reads `models/gemma-4-26B-A4B-it-qat-q4_0-unquantized`. Device spans come from the process memory manager. `open_runtime` takes `owner` and every span from that opening uses it. `close` sweeps that string. A command that omits `owner` mints one from this runtime's id. The opening reads the memory budget and keeps every expert layer that fits after `resident.bin`, the scratch, and the key/value cache. The cache starts at 256 tokens and doubles. Growth releases layer files until the new cache and at least one layer file fit. A layer that is not resident is read into the oldest slot before that layer runs. The opening refuses when one layer file does not fit. A request logs prompt tokens, a cache hit or miss, and the prefill and decode counts while those phases run. The prefill count stays short of the prompt until the chunk's command buffer has finished. Dense projections stay q4_0. Decode reads those in `gemv_q4_0` and the routed experts in `gemv_q4_0_routed`. Prefill reads a chunk of 1024 tokens.

## Kernels

`kernels` compiles this package's shader library and dispatches one fp8 `matmul2d`, one fp4 `matmul2d`, one float16 `matmul2d`, one 64×64 float16 `matmul2d` of a dequantized q4_0 matrix, one q4_0 dequant into float16, one q4_0 matrix-vector product, one short q4_0 matrix product, and one tiled q4_0 matrix product. The left operand of `matmul2d` is float16, the destination is float32, and a quantized right-hand tensor is dequantized inside the op. q4_0 is not a `matmul2d` right-hand type, so that check dequantizes it first. The fp8 and fp4 checks compare that product with the packed restore. The q4_0 checks compare the dequantized rows, the matrix-vector product, the short product, the tiled product, and the 64×64 product with the q4_0 restore. A missing kernel stays missing.

## Record

`plan` prints packed sizes from the checkpoint shapes. `quantize` streams a local bfloat16 checkout into `models/gemma-4-26B-A4B-it-q4_0`. Every quantized matrix is q4_0. A block is 32 values. The scale is the QAT lattice step, stored as bfloat16 with the ggml sign so the positive peak maps to code −8. A block that is not on that lattice uses the signed peak divided by −8. The codes are −8..7. The low nibble is element `i` and the high nibble is element `i + 16`. K is padded to a multiple of 32. A finished directory has `manifest.json` with `complete: true`. Running quantize again on that directory returns it. An unfinished directory resumes from `quantize_progress.json`. The 128 experts of a layer are packed together, and a resident matrix of 8192 or more rows is packed in row spans of 8192. Each worker uses one BLAS thread.

`plan` reports resident matrices of 1,649,931,264 bytes, the float16 scratch of 1,476,395,008 bytes, float16 vectors of 70,474,908 bytes, and expert images of 12,846,366,720 bytes. Routed experts stay in `experts/<layer>.bin`. `experts/offsets.bin` is the byte offset of each image inside that layer file. Image order is expert 0 through 127, gate-up then down. Opening the record reads each resident layer file straight into that q4_0 image and shows that read while it runs. A token indexes eight experts in that image. Resident matrices and the float16 vectors are `resident.bin` with `resident.json`. The token embedding, the attention projections, the shared MLP, and the vision linears are q4_0. The router, the norms, `router.scale`, `per_expert_scale`, `layer_scalar`, and the vision vectors stay float16. The drafter is not in this record. The vision tower stays in that file and is loaded on the first image. A text-only open does not read it. The runtime keeps the resident q4_0 bytes. Decode reads those bytes in `gemv_q4_0`. The eight routed experts of a token launch from the ids the router wrote on device, one `gemv_q4_0_routed` per projection, and the token does not read those ids back. A prefill chunk is 1024 tokens and submits every ten layers, so the prefill count advances while the device runs. Local attention is `attend_span4`, four queries sharing each key load. Global attention is `attend_span`. Expert prefill groups the routed rows on device. The slot tables and the matmul grid stay there, so the host does not read the ids. Every layer's 128 experts are repacked to fp4 once while the runtime opens, for as many layers as the budget still holds. A layer that does not fit is repacked again on the next chunk. Occupied slots are padded to 64 and multiplied with `matmul_fp4_64_batch`. The down projection pads K from 704 to 768. A batch of eight or fewer tokens reads the packed blocks in `gemm_q4_0_n`. A longer batch dequantizes one matrix into a reused float16 buffer and multiplies it with `matmul2d`. The atlas is not expanded. `plan` still prints the float16 size a full-matrix dequant would write. The router stays float16 and uses `matmul2d`. Bandwidth and kernel ceilings are in [ceilings.md](ceilings.md).

## Forward

The text decoder has 30 layers, hidden size 2816, and a tied embedding of 262,144 rows. Layers 5, 11, 17, 23, and 29 are global. A global layer stores keys and values. The value is an RMSNorm, with no scale, of the key projection, and it is not rotated. Local values are that same norm of the value projection. Attention scores are the raw dot. The other 25 layers are local, with a sliding window of 1024. Local heads are 16 query heads of dimension 256 and 8 key and value heads. Global heads are 16 query heads of dimension 512 and 2 key heads. Full rotary embeddings use θ = 10,000 on every local pair. Global layers use proportional rotary embeddings, θ = 1,000,000, on the first quarter of the pairs (Barbero et al.). The remaining pairs are the identity. The rotation is the first half against the second half. RMSNorm uses the stored scale as the multiplier, with ε = 10⁻⁶. Query and key norms are one vector of the head dimension, applied to each head. The shared MLP and each routed expert use the tanh approximation of GELU. The router is a float16 product. Its input is RMSNorm with the stored `router.scale` multiplied by `1/sqrt(hidden)`. A device kernel keeps eight of 128 experts, renormalizes them, and multiplies by `per_expert_scale`. The token embedding row is dequantized on device and multiplied by `sqrt(hidden)`. Final logits use the tied embedding, with no extra scale, and the soft cap 30, `30 · tanh(logits / 30)`. Temperature, top-k, top-p, and the presence penalty run on device. The CPU reads eight expert ids per layer and the one sampled token. Dispatches in one layer share a command buffer until that read. The next buffer waits on a fence. Query and key norms are one launch per tensor. Decode attention is `attend_decode`. One simd walks a short cache. At 256 keys the walk splits across four simdgroups, and at 1024 keys across eight. They merge one online softmax. Prefill local attention is `attend_span4`. Prefill global attention is `attend_span`.

Attention and both feed-forward branches add at scale one. The dense MLP uses `pre_feedforward_layernorm` and `post_feedforward_layernorm_1`. Routed experts use `pre_feedforward_layernorm_2` and `post_feedforward_layernorm_2`. `post_feedforward_layernorm` normalizes the sum of those branches. `layer_scalar` then multiplies the hidden state. A generation that collects 6 carrots is what accepts the block.

An image request loads the 550M vision tower from those packed q4_0 rows. The resize is Algorithm 1: pooled patch 48, at most 280 soft tokens, bicubic, then rescale by 1/255. Each patch is 16×16×3 in row order. The encoder has 27 layers of width 1152 and 16 heads of dimension 72. Attention is non-causal and the score is the dot times `1/sqrt(72)`. Axial 2D-RoPE uses θ = 100: the first half of the head rotates with the row and the second half with the column, each half pairing its first 18 values with its second 18. The absolute table adds axis 0 at the row and axis 1 at the column after a per-token standardize (`std_scale`, `std_bias`, ε = 10⁻⁶). Each block matches the text attention residual without a layer scalar: RMSNorm, attention, post-attention RMSNorm, residual, then the tanh-GELU MLP with its pre and post RMSNorms. A 3×3 average and `embedding_projection` replace `<|image|>`. Those linears are the q4_0 rows already in the record, so a second quantize is not required. The expanded length is `prompt_tokens`. An image prompt does not enter the prefix file.

The served window is 131,072 tokens. The checkpoint position limit is 262,144. The live key and value cache is float16. It starts at 256 tokens and doubles. The prefix file stores local keys and values, and global keys and values, as fp8. The pack reads one live float16 layer at a time, so the host does not keep a second copy of the cache. An exact-length file is not sampled. The next token is still stepped. A prompt that extends the live tokens continues. Any other prompt writes the live sequence and loads the longest stored strict prefix.

The chat template rendered at request time is the canonical Gemma 4 template published 2026-07-09, stored beside this package. The copy in the quantized record is not rendered. A request passes its `tools` into that template. OpenAI tool-call arguments arrive as a JSON string and are decoded to an object before render, which is the form the template accepts. A completion with `stream` false is one JSON object. A completion sends the trace as `reasoning` and `reasoning_content` when the model wrote one. A whitespace-only thought is omitted. `content` is the reply, and it is null when the model only calls a tool. A completion with `stream` true sends those fields as each token is sampled, then `tool_calls` when a call is present. Text after a call is split the same way: a later thought is reasoning, and the remaining text is the reply. An unclosed call stays in the reply. A tool call is `<|tool_call>call:` through `<tool_call|>`, and `<|tool_response>` is a stop. Thinking off ends the prompt with an empty `<|channel>thought` so this size does not open a ghost channel. Thinking on, after a tool result, leaves that model turn open and starts the next thought channel. A raw thought is rendered only on a tool-call message that is still after the latest user message, so it stays between tool calls and drops when the next user turn starts. A plain answer's thought is not rendered. The template has no reasoning-effort ladder. Thinking is `enable_thinking`. Registration copies the thinking and instruct rows from `sampling.py`. Both rows are temperature 1.0, top-p 0.95, top-k 64, and presence penalty 0. A request that omits the variant uses the thinking row. `enable_thinking` false uses the instruct row. Temperature 0 is an argmax. A presence penalty is subtracted once from each distinct token already drawn. Stop ids are 1, 106, and 50. A request `stop` string ends the completion and stays out of the reply. Filling the completion cap sets `finish_reason` to `length`. Every completion takes the reply from outside `<|channel>thought` … `<channel|>`. Text before that channel stays in the reply. A `<|tool_call>` before the close ends the trace. An open thought, including the channel a tool result leaves open, is `reasoning_content` and is not the reply. `tests/test_gemma4_26b_a4b_smoke.py` runs the carrot prompt: greedy instruct, the instruct card, and the thinking card.
