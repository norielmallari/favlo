# Gemma 4 26B-A4B

As-built note for the `gemma4-26b-a4b` pipeline. The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

`handle_chat` is a `LanguagePipeline`. The completion, the sampler, and the stream stay in this package. Clients reach this pipeline through `favlo serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `plan`, `quantize`, `kernels`, and `complete` require `favlo --gemma4-26b-a4b`. That flag loads `pipelines/metal41/gemma4-26b-a4b.py`, which loads `gemma4_26b_a4b`.

The official checkpoint is [google/gemma-4-26B-A4B-it](https://huggingface.co/google/gemma-4-26B-A4B-it). Those weights are under the [Apache License, Version 2.0](https://ai.google.dev/gemma/docs/gemma_4_license). `quantize` does not download. With no `--src` it reads `models/gemma-4-26B-A4B-it-qat-q4_0-unquantized`. Device spans come from the process memory manager. `open_runtime` takes `owner` and every span from that opening uses it. `close` sweeps that string. A command that omits `owner` mints one from this runtime's id. The opening reads the memory budget and refuses when `resident.bin` plus the expert atlas is larger than that budget. Opening repacks each expert layer from q4_0 to fp4 E2M1 with an E8M0 scale and releases that q4_0 image. Dense projections stay q4_0. Decode reads those in `gemv_q4_0` and the routed experts in `gemv_fp4_routed`. Prefill reads a chunk of 1024 tokens.

## Kernels

`kernels` compiles this package's shader library and dispatches one fp8 `matmul2d`, one fp4 `matmul2d`, one float16 `matmul2d`, one 64×64 float16 `matmul2d` of a dequantized q4_0 matrix, one q4_0 dequant into float16, one q4_0 matrix-vector product, one short q4_0 matrix product, and one tiled q4_0 matrix product. The left operand of `matmul2d` is float16, the destination is float32, and a quantized right-hand tensor is dequantized inside the op. q4_0 is not a `matmul2d` right-hand type, so that check dequantizes it first. The fp8 and fp4 checks compare that product with the packed restore. The q4_0 checks compare the dequantized rows, the matrix-vector product, the short product, the tiled product, and the 64×64 product with the q4_0 restore. A missing kernel stays missing.

## Record

`plan` prints packed sizes from the checkpoint shapes. `quantize` streams a local bfloat16 checkout into `models/gemma-4-26B-A4B-it-q4_0`. Every quantized matrix is q4_0. A block is 32 values. The scale is the QAT lattice step, stored as bfloat16 with the ggml sign so the positive peak maps to code −8. A block that is not on that lattice uses the signed peak divided by −8. The codes are −8..7. The low nibble is element `i` and the high nibble is element `i + 16`. K is padded to a multiple of 32. A finished directory has `manifest.json` with `complete: true`. Running quantize again on that directory returns it. An unfinished directory resumes from `quantize_progress.json`. The 128 experts of a layer are packed together, and a resident matrix of 8192 or more rows is packed in row spans of 8192. Each worker uses one BLAS thread.

`plan` reports resident matrices of 1,649,931,264 bytes, the float16 scratch of 1,476,395,008 bytes, float16 vectors of 70,474,908 bytes, and expert images of 12,846,366,720 bytes. Routed experts stay in `experts/<layer>.bin`. `experts/offsets.bin` is the byte offset of each image inside that layer file. Image order is expert 0 through 127, gate-up then down. Opening the record reads every layer file, repacks gate-up and down to fp4, and releases the q4_0 bytes. A token indexes eight experts in that fp4 image. Resident matrices and the float16 vectors are `resident.bin` with `resident.json`. The token embedding, the attention projections, the shared MLP, and the vision linears are q4_0. The router, the norms, `router.scale`, `per_expert_scale`, `layer_scalar`, and the vision vectors stay float16. The drafter is not in this record. The vision tower is packed and is not executed. The runtime keeps the resident q4_0 bytes. Decode reads those bytes in `gemv_q4_0`. The eight routed experts of a token launch from the ids the router wrote on device, one `gemv_fp4_routed` per projection, and the token does not read those ids back. A prefill chunk is 1024 tokens. Local attention is `attend_span4`, four queries sharing each key load. Global attention is `attend_span`. Expert prefill sorts the routed rows and runs one fp4 `matmul2d` over slots of 64 tokens. A batch of eight or fewer tokens reads the packed blocks in `gemm_q4_0_n`. A longer batch dequantizes one matrix into a reused float16 buffer and multiplies it with `matmul2d`. The atlas is not expanded. `plan` still prints the float16 size a full-matrix dequant would write. The router stays float16 and uses `matmul2d`. Bandwidth and kernel ceilings are in [ceilings.md](ceilings.md).

## Forward

The text decoder has 30 layers, hidden size 2816, and a tied embedding of 262,144 rows. Layers 5, 11, 17, 23, and 29 are global. A global layer stores keys and values. The value is an RMSNorm, with no scale, of the key projection, and it is not rotated. Local values are that same norm of the value projection. Attention scores are the raw dot. The other 25 layers are local, with a sliding window of 1024. Local heads are 16 query heads of dimension 256 and 8 key and value heads. Global heads are 16 query heads of dimension 512 and 2 key heads. Full rotary embeddings use θ = 10,000 on every local pair. Global layers use proportional rotary embeddings, θ = 1,000,000, on the first quarter of the pairs (Barbero et al.). The remaining pairs are the identity. The rotation is the first half against the second half. RMSNorm uses the stored scale as the multiplier, with ε = 10⁻⁶. Query and key norms are one vector of the head dimension, applied to each head. The shared MLP and each routed expert use the tanh approximation of GELU. The router is a float16 product. Its input is RMSNorm with the stored `router.scale` multiplied by `1/sqrt(hidden)`. A device kernel keeps eight of 128 experts, renormalizes them, and multiplies by `per_expert_scale`. The token embedding row is dequantized on device and multiplied by `sqrt(hidden)`. Final logits use the tied embedding, with no extra scale, and the soft cap 30, `30 · tanh(logits / 30)`. Temperature, top-k, top-p, and the presence penalty run on device. The CPU reads eight expert ids per layer and the one sampled token. Dispatches in one layer share a command buffer until that read. The next buffer waits on a fence. Query and key norms are one launch per tensor. Decode attention is `attend_span`, one simd per query head. Prefill local attention is `attend_span4`. Prefill global attention is `attend_span`.

Attention and both feed-forward branches add at scale one. The dense MLP uses `pre_feedforward_layernorm` and `post_feedforward_layernorm_1`. Routed experts use `pre_feedforward_layernorm_2` and `post_feedforward_layernorm_2`. `post_feedforward_layernorm` normalizes the sum of those branches. `layer_scalar` then multiplies the hidden state. A generation that collects 6 carrots is what accepts the block.

The served window is 131,072 tokens. The checkpoint position limit is 262,144. The live key and value cache is float16. It starts at 256 tokens and doubles. The prefix file stores local keys and values, and global keys and values, as fp8. An exact-length file is not sampled. The next token is still stepped. A prompt that extends the live tokens continues. Any other prompt writes the live sequence and loads the longest stored strict prefix.

The chat template rendered at request time is the canonical Gemma 4 template published 2026-07-09, stored beside this package. The copy in the quantized record is not rendered. A request passes its `tools` into that template. OpenAI tool-call arguments arrive as a JSON string and are decoded to an object before render, which is the form the template accepts. A completion with `stream` false is one JSON object. A tool call is `<|tool_call>call:` through `<tool_call|>`, and `<|tool_response>` is a stop. Thinking off ends the prompt with an empty `<|channel>thought` so this size does not open a ghost channel. Thinking on, after a tool result, leaves that model turn open and starts the next thought channel. A raw thought is rendered only on a tool-call message that is still after the latest user message, so it stays between tool calls and drops when the next user turn starts. A plain answer's thought is not rendered. The template has no reasoning-effort ladder. Thinking is `enable_thinking`. Registration copies the thinking and instruct rows from `sampling.py`. Both rows are temperature 1.0, top-p 0.95, top-k 64, and presence penalty 0. A request that omits the variant uses the thinking row. `enable_thinking` false uses the instruct row. Temperature 0 is an argmax. A presence penalty is subtracted once from each distinct token already drawn. Stop ids are 1, 106, and 50. A thinking reply splits the answer at `<channel|>`. `tests/test_gemma4_26b_a4b_smoke.py` runs the carrot prompt: greedy instruct, the instruct card, and the thinking card. The reply collects 6 carrots. The isolated decode sum is [research/kernel-ceilings.md](research/kernel-ceilings.md). The recorded prefill and decode runs are [research/recorded-forward.md](research/recorded-forward.md). Harness scores are in [benchmarks.md](benchmarks.md).
