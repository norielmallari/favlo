# Qwen3.8-27B

As-built note for the `qwen38-27b` pipeline. The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

Clients reach this pipeline through `madmetal serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `kernels`, `quantize`, `bf16`, `complete`, and `models` require `madmetal --qwen38-27b`. That flag loads `qwen38-27b.py`, which loads `qwen38_27b`. The package does not import `qwen38_flash_next` or `qwen36_35b_a3b`.

## Kernels

`kernels` compiles this package's shader library and fails if any kernel in that library does not produce a pipeline. It then dispatches the 64×64 and 64×32 fp4 `matmul2d` tiles, the fp4 GEMV, the four-row fp4 GEMV, multiplicative RMSNorm, SwiGLU, one Gated DeltaNet step, the 10240-channel convolution, an E4M3 decode, partial RoPE at position 0, and a four-token causal fp8 attention. The host formulas for those dispatches live in `qwen38_27b/checks.py`.

The DeltaNet state is float32, 48 heads of `128×128`. The step decays the state by \(\alpha\), writes \(\beta(v - Sk)k^\top\), and reads with the query. \(\alpha = \exp(-\exp(A_{\log})\mathrm{softplus}(a + \mathrm{dt\_bias}))\) and \(\beta = \mathrm{sigmoid}(b)\). Decode applies that step once per token. Prefill uses the same recurrence across the tokens of a chunk of at most 2048. Query and key are repeated three times across the 48 value heads. The mixed vector is 10240 wide (query at 0, key at 2048, value at 4096) and the output gate is 6144 wide. The head RMSNorm multiplies by the stored gain, \(x / \mathrm{rms} \cdot w\), then the gate is SiLU. `in_proj_a` and `in_proj_b` are stored with 64 rows so the matmul tile is full; the recurrence reads heads 0 through 47. This form is what `kernels` checks. A BF16 layer step has not accepted it.

## Record

`quantize` streams a Hugging Face BF16 checkout into `models/Qwen3.8-27B-madmetal-fp8-fp4`. Every matrix is uniform fp4 E2M1 with an E8M0 scale every 32 along K. That includes the embedding, the projections, the feed-forward, `lm_head`, the MTP block, and the vision tower. Rows are stored as a multiple of 64 and K as a multiple of 256. One-dimensional parameters stay float16: RMSNorm gains, `A_log`, `dt_bias`, and biases. The depthwise convolution stays float16 with shape `[10240, 4]`. A finished directory has `manifest.json` with `complete: true`. Running quantize again on that directory returns it. An unfinished directory resumes from `quantize_progress.json`.

`bf16` does not run a layer against the stored BF16 values.

## Forward

`serve` and `complete` apply the prompt in chunks of at most 2048 tokens, one command buffer per chunk, then take an argmax one token at a time. `serve` draws a load row while the record, the cache, and the scratch are copied, then a prefill row that counts tokens as each chunk finishes. The decode row shows the output tok/s and does not draw a bar. Each row closes with that phase's tok/s line. A streaming client receives each argmax token as a `chat.completion.chunk` with `id`, `object`, `created`, and `model`, framed as HTTP chunked encoding. An empty delta is sent as each prefill chunk finishes, so the stream stays open through the copy. Reasoning is `delta.reasoning_content` until `</think>`, and the reply is `delta.content`. A tool call streams as `delta.tool_calls` with an `index`: the name when `<function=` closes, then argument pieces that concatenate to one JSON object. The chunk before `data: [DONE]` carries `usage`. A closed client, SIGINT, or SIGTERM stops the forward before the next chunk and before the next token. A chunk that has already been submitted runs to completion. A chunk's projections are fp4 `matmul2d` tiles of 64 by 64. The argmax token is a four-row fp4 GEMV. The vocabulary reduction stays on device; the host keeps the lowest index among the partial winners.

The position limit is the checkpoint's `max_position_embeddings` (262,144), reduced to a multiple of 2048 when the resident record and the cache do not both fit in the memory cap. `serve --max-memory` and `complete --max-memory` set that cap, as a byte count or a `GiB` or `MiB` size. Omitting it uses the reclaimable memory at load. The resident file, the key/value planes, the DeltaNet state, and the chunk workspace are allocated inside that cap. There is no expert atlas.

The live key/value cache is fp8 E4M3 on the 16 full-attention layers. A key is `[head, token, channel]` with an E8M0 scale every 32 channels. A value is `[head, channel, token]` with an E8M0 scale every 32 tokens, so the score product and the value mix are both `matmul2d`. One head at one position is 264 bytes. One token across the 16 layers is 33,792 bytes. 65,536 tokens are 2.06 GiB. The full 262,144-token cache is 8.25 GiB. Prefill pads the token count so the six queries of a key/value head fill a 64-row tile, scores 2048 keys at a time, and mixes values with the context length as the token stride. Decode pads the six queries to eight rows, drops the two padding rows, and reduces the value mix in blocks of 512 keys. Softmax runs on the score tile. `complete` takes `--kv-cache e4m3`. A later prompt that begins with the tokens already in that cache continues from the first new token. The record does not store that cache.

RMSNorm on the residual stream, the final norm, and the query and key is the zero-centered form, \(x / \mathrm{rms} \cdot (1 + w)\). The Gated DeltaNet head norm multiplies by \(w\). Full attention applies that norm to the query and the key over 256 channels, then partial RoPE on the first 64 channels with \(\theta = 10^{7}\). A text position is written on every mRoPE axis, so the rotation is plain RoPE. The scale is \(1/\sqrt{256}\). `q_proj` is 256 query channels and then 256 gate channels per head. The sigmoid of the gate multiplies the attention output before `o_proj`. The feed-forward is SwiGLU with intermediate width 17408.

One decode step reads the fp4 language projections and the head. With `in_proj_a` and `in_proj_b` stored at 64 rows, that image is 13.18 GiB. The embedding contributes one row. Convolution and norms are float16. At 307 GB/s that 13.18 GiB read is 21.7 tok/s before the key/value cache. That figure is the byte count divided by that bandwidth.

A warm run with the full 262,144-token cache allocated measured 353.54 tok/s on a 2048-token prefill (5.79s) and 15.29 tok/s on 64 argmax tokens after a 58-token prompt (4.19s). The 2048-token prefill repeated one token id. The decode prompt was the grove question. A later run that read repository files until the prompt passed 65,536 tokens, and continued to 83,461, measured 230.07 tok/s prefill over 83,435 tokens (362.65s) and 13.18 tok/s decode over 39 tokens (2.96s). The last request started from a 45,789-token cache hit and prefilled the remaining 37,672 tokens at 193.43 tok/s.

The MTP block is packed and is not drafted, so the token is the backbone argmax. Vision weights are packed when the checkout has them. A text request does not run the tower.

The chat template is the checkout's `chat_template.jinja`. Thinking stays open unless the request sets `enable_thinking` false. A request that omits `reasoning_effort`, or sends `none`, leaves the template default, xhigh. The completion is an argmax. Stop ids are 248046 and 248044. A `tool_choice` that names one function closes thinking when the request did not set it. A function with parameters forces `<tool_call><function=name>` as the start of the completion. A function with no parameters forces that call closed and does not continue past it. The reply parser turns a finished call into an OpenAI `tool_calls` message.

`complete` writes one argmax grove completion to `grove.json` in the record directory. `models` reads the shared registry. Registration copies the thinking and instruct rows from `sampling.py`. The forward does not apply those temperatures, top-p, top-k, or presence penalties. A request that omits the variant uses the thinking row for the template. `enable_thinking` false uses the instruct row for the template.
