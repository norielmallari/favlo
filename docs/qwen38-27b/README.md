# Qwen3.8-27B

As-built note for the `qwen38-27b` pipeline. The process contract is [../../ARCHITECTURE.md](../../ARCHITECTURE.md). This directory wins for this pipeline's records and kernels. Another pipeline does not edit it.

Clients reach this pipeline through `favlo serve`. `GET /v1/models` lists it once a record is registered, and the `model` field on `POST /v1/chat/completions` loads it. `kernels`, `quantize`, `bf16`, `complete`, and `models` require `favlo --qwen38-27b`. That flag loads `pipelines/metal41/qwen38-27b.py`, which loads `qwen38_27b`. The package does not import `qwen38_flash_next` or `qwen36_35b_a3b`.

The official checkpoint is [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B). Those weights are under the Apache License, Version 2.0.

## Kernels

`kernels` compiles this package's shader library and fails if any kernel in that library does not produce a pipeline. It then dispatches the 64×64 and 64×32 fp4 `matmul2d` tiles, the 32×128 fp4 and fp8 tiles, the fp8 64×64 weight tile, the fp4 GEMV, the four-row fp4 GEMV, the four-row fp8 GEMV, the fused fp8 gate and up projection, the two-activation fp4 GEMV, multiplicative RMSNorm, SwiGLU, one Gated DeltaNet step, the 10240-channel convolution, an E4M3 decode, partial RoPE at position 0, a four-token causal fp8 attention, the tanh GELU, and the erf GELU. The host formulas for those dispatches live in `qwen38_27b/checks.py`.

The DeltaNet state is float32, 48 heads of `128×128`. The step decays the state by \(\alpha\), writes \(\beta(v - Sk)k^\top\), and reads with the query. \(\alpha = \exp(-\exp(A_{\log})\mathrm{softplus}(a + \mathrm{dt\_bias}))\) and \(\beta = \mathrm{sigmoid}(b)\). Decode applies that step once per token. Prefill uses the same recurrence across the tokens of a chunk of at most 2048. Each head keeps its state row on the thread for that chunk and writes the row back once. Query and key are repeated three times across the 48 value heads. The mixed vector is 10240 wide (query at 0, key at 2048, value at 4096) and the output gate is 6144 wide. The head RMSNorm multiplies by the stored gain, \(x / \mathrm{rms} \cdot w\), then the gate is SiLU. `in_proj_a` and `in_proj_b` are stored with 64 rows so the matmul tile is full; the recurrence reads heads 0 through 47. This form is what `kernels` checks. A BF16 layer step has not accepted it.

## Record

`quantize` streams a Hugging Face BF16 checkout into `models/Qwen3.8-27B-fp4`. Every matrix is fp4 E2M1 with an E8M0 scale every 32 along K. That includes the embedding, the projections, the feed-forward, `lm_head`, the MTP block, and the vision tower. Rows are stored as a multiple of 64 and K as a multiple of 256. One-dimensional parameters stay float16: RMSNorm gains, `A_log`, `dt_bias`, and biases. The depthwise convolution stays float16 with shape `[10240, 4]`. `--ffn-fp8` is a percentage of the 64 language feed-forward layers. Omitting it, or passing an empty value, promotes none. `100` stores all 64 as fp8 E4M3 and writes `models/Qwen3.8-27B-fp8`. A percentage in between writes `models/Qwen3.8-27B-fp8-fp4`. The layer count is the largest whole number that does not exceed that percentage, so `20` is 12 layers. Those layers are the highest BF16-to-fp4 relative errors. Gate, up, and down move together. The MTP feed-forward stays fp4. A partial percentage writes `ffn_error.json` before packing. A finished directory has `manifest.json` with `complete: true`. Running quantize again on that directory returns it when the percentage matches. An unfinished directory resumes from `quantize_progress.json`. The format bound is [research/ffn-fp8-budget.md](research/ffn-fp8-budget.md). Prefill reads an fp8 feed-forward matrix with `prefill_fp8_n64`. Decode reads gate, up, and down with `gemv_fp8_x4`. A decode step submits every 4 layers as its own command buffer.

`bf16` does not run a layer against the stored BF16 values.

## Forward

`serve` and `complete` apply the prompt in chunks of at most 2048 tokens, then draw one token at a time. A chunk submits every 4 layers as its own command buffer while every feed-forward layer it runs is in the device buffer. A layer that stays in the record is copied into one stage before its matmul, and the next copy waits until that command buffer has finished. Temperature 0 is the on-device argmax. A positive temperature, a presence penalty, a frequency penalty, or a logit bias reads the logits and samples on the host. `serve` draws a load row while the wired tensors are read in file order, then the cache and the scratch are copied, then a prefill row that counts tokens as each chunk finishes. The decode row shows the output tok/s and does not draw a bar. Each row closes with that phase's tok/s line. The prefill clock starts at the uncached forward, after the prefix restore, and ends when the first output token is sampled. The forward that produced that token stays in prefill. The decode clock starts at that same sample and ends at the last sample. A token sent between samples stays in decode, and the last send stays outside it. The prompt prefix write stays outside prefill. One output token leaves the decode duration at 0. The phase line and `usage.timings` use those seconds. `prompt_n` is the uncached prompt count and `predicted_n` is the completion count. A zero duration writes a rate of 0. A streaming client receives each token as a `chat.completion.chunk` with `id`, `object`, `created`, and `model`, framed as HTTP chunked encoding. An empty delta is sent as each prefill chunk finishes, so the stream stays open through the copy. Reasoning is `delta.reasoning_content` until `</think>`, and the reply is `delta.content`. A tool call streams as `delta.tool_calls` with an `index`: the name when `<function=` closes, then argument pieces that concatenate to one JSON object. `tool_choice` `none` leaves that text in `delta.content` and does not send `tool_calls`. The chunk before `data: [DONE]`, and a non-streaming completion, carry the same `usage`: `prompt_tokens`, `completion_tokens`, `total_tokens`, `context_length`, and `prompt_tokens_details.cached_tokens`. `context_length` is the served window, 131072. A closed client, SIGINT, or SIGTERM stops the forward before the next chunk and before the next token. A chunk that has already been submitted runs to completion. A chunk's projections are `matmul2d` tiles of 64 by 64. The down projection uses a 32 by 128 tile. The argmax token is a four-row fp4 GEMV. The vocabulary reduction stays on device; the host keeps the lowest index among the partial winners.

The position limit is the checkpoint's `max_position_embeddings` (262,144), and the served window stops at 131,072. The live length starts at 2,048 and grows by 2,048 to cover the prompt and the next decoded token. `serve --max-memory` and `complete --max-memory` set the byte cap for that fit, as a byte count or a `GiB` or `MiB` size. Omitting it uses the reclaimable memory at the moment of the fit. The fit claims the prefill workspace, the decode buffers, the DeltaNet state, and the convolution history first, then the key/value cache and the attention scratch at the length being fitted. Text tensors other than feed-forward images are claimed next: the Gated DeltaNet projections, the full-attention projections, the embedding, `lm_head`, and the float16 vectors. Vision tensors stay in the record file until a message contains an image. That request copies the tower, runs its 27 blocks, and replaces the image placeholder with one token per 2×2 patch block. Text keeps one position id on every RoPE axis. An image token keeps a constant temporal id and writes the merged row and column on the other two. Bytes left after that claim wire whole feed-forward layers, from layer 0 upward. A layer that does not fit is read from the record into one stage before that layer runs. The stage is the size of the largest unwired layer. When the prompt still does not fit, the MTP head leaves the device buffer: its projections, its feed-forward, its norms, its key/value plane, and the draft mix buffer. Prefill skips the MTP block, and decode already does not run it. Language feed-forward layers then leave from the last index downward. The cache is not shortened to bring a layer back. A growth copies the live cache to the host and reserves that copy in the budget before it chooses the next image. When the next image keeps the same weights, only the key/value planes are replaced and the weight buffer stays. When the reserved budget cannot cover the next token, the current image stays and decode stops at the live length. A growth between samples stays inside the decode clock. When the MTP head is already gone and every language feed-forward layer is unwired, a further token stops at the live length. There is no expert atlas. A different folder or a different pipeline closes this runtime before the next one loads. `close` writes the live prefix, finishes an open command buffer, and returns the resident buffer, the key/value planes, and the scratch to the kernel before it drops the Metal device.

The live key/value cache is fp8 E4M3 on the 16 full-attention layers. A key is `[head, token, channel]` with an E8M0 scale every 32 channels. A value is `[head, channel, token]` with an E8M0 scale every 32 tokens, so the score product and the value mix are both `matmul2d`. One head at one position is 264 bytes. One token across the 16 language layers is 33,792 bytes. 65,536 tokens are 2.06 GiB. The full 262,144-token language cache is 8.25 GiB. While the MTP head is resident the fit counts that plane too, 2,112 bytes per token, so a drafted record is 35,904 bytes per token (9,412,018,176 bytes at 262,144). Prefill pads the token count so the six queries of a key/value head fill a 64-row tile, scores 2048 keys at a time, and mixes values with the context length as the token stride. Decode pads the six queries to eight rows, drops the two padding rows, and mixes every 512-key block of a head in one dispatch. Softmax writes float32 weights on the score tile. Each value-mix window divides by that row's peak, multiplies in float16, and restores the peak. `complete` takes `--kv-cache e4m3`. A prompt that extends the live tokens continues from the first new token. Any other prompt writes that sequence through the shared prefix store and loads the longest stored strict prefix of the new tokens. That load reads one stored plane, copies it into the cleared device plane, and drops the host bytes before it reads the next plane. The file holds the packed key and value positions, the DeltaNet state, and the convolution history. While the MTP head is resident the file also needs that plane, and a file without it is not installed. After the head has been dropped, the 16 language planes are enough. The weight record does not store that cache. An exact-length file is not sampled; the next token is still stepped.

RMSNorm on the residual stream, the final norm, and the query and key is the zero-centered form, \(x / \mathrm{rms} \cdot (1 + w)\). The Gated DeltaNet head norm multiplies by \(w\). Full attention applies that norm to the query and the key over 256 channels, then partial RoPE on the first 64 channels with \(\theta = 10^{7}\). A text position is written on every mRoPE axis, so the rotation is plain RoPE. The scale is \(1/\sqrt{256}\). `q_proj` is 256 query channels and then 256 gate channels per head. The sigmoid of the gate multiplies the attention output before `o_proj`. The feed-forward is SwiGLU with intermediate width 17408.

One decode step reads the fp4 language projections and the head. With `in_proj_a` and `in_proj_b` stored at 64 rows, that image is 13.18 GiB. The embedding contributes one row. Convolution and norms are float16. At 307 GB/s that 13.18 GiB read is 21.7 tok/s before the key/value cache. That figure is the byte count divided by that bandwidth. The isolated projection sum is a measurement in [research/kernel-ceilings.md](research/kernel-ceilings.md).

The MTP block is one full-attention layer. At each position it reads the backbone residual and the embedding of the next token. Each vector is RMSNormed. The embedding half is concatenated in front of the residual half, which is the order that matches this checkpoint; equation (21) of the DeepSeek-V3 report writes the residual half first. `mtp.fc` projects that 10,240-wide vector back to 5,120. The layer then runs with the same kernels as language layer 3, and `mtp.norm` plus the shared `lm_head` argmax is the draft. Prefill fills that plane while the head is resident. A two-token projection (`gemv_fp4_span2` and the span forms of the fused projections) reads each weight once. On one prompt its argmax matched two serial steps for each of the first six pairs, and the GDN input projection differed by at most 2e-6. Keeping that state changed the completion by the tenth token, so decode stays the serial argmax and does not substitute the draft. The paired run is [research/span-draft.md](research/span-draft.md). Vision weights are packed when the checkout has them. A text request does not run the tower.

The chat template is the checkout's `chat_template.jinja`. An assistant turn with no reasoning renders `<think>\n</think>` while thinking is on, the same bytes as a generation that closes thinking immediately, so the next turn keeps the stored tokens. The checkout template writes a blank line in that block. Render keeps the blank line only when thinking is off. Thinking stays open unless the request sets `enable_thinking` false. A request that omits `reasoning_effort`, or sends `none`, leaves the template default, xhigh. The completion uses the request's temperature, top-p, top-k, presence penalty, frequency penalty, and logit bias. A field the request omits comes from the sampling card for that variant. An omitted `max_tokens` does not cap the completion. It stops on a stop id or at the last context position. The served window stops at 131072 tokens. `settings.json` key `max_tokens` is that cap when the request omits it. Temperature 0 is an argmax of the adjusted logits. A positive temperature keeps the top-k scores, then the nucleus (Holtzman et al.). Presence subtracts once from each completion token already drawn. Frequency subtracts once for every earlier copy of that token. Both follow the OpenAI logit update. A span of 16 to 64 tokens that copies the span before it ends the completion. Stop ids are 248046 and 248044. A `tool_choice` that names one function closes thinking when the request did not set it. A function with parameters forces `<tool_call><function=name>` as the start of the completion. A function with no parameters forces that call closed and does not continue past it. The reply parser turns a finished call into an OpenAI `tool_calls` message. `tool_choice` `none` keeps the call text in `content`.

Harness scores for this pipeline are in [benchmarks.md](benchmarks.md). `complete` writes one argmax carrot completion to `carrots.json` in the record directory. `tests/test_qwen38_27b_smoke.py` runs that prompt on this pipeline. The reply collects 6 carrots. Instruct runs at the instruct card unless the request sets a field. Thinking runs when the checkpoint template opens a think block, at the template default and at each reasoning effort that template names, and the draw uses the thinking card. `models` reads the shared registry. Registration copies the thinking and instruct rows from `sampling.py`. A request that omits the variant uses the thinking row. `enable_thinking` false uses the instruct row.
