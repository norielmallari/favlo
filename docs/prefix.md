# Prefix cache

As-built SSD prefix store. The map is [../ARCHITECTURE.md](../ARCHITECTURE.md). What a pipeline puts in the regions, and whether an exact-length file can be sampled, is that pipeline's note.

`src/favlo/prefix.py` stores one sequence as token ids plus named regions under `~/.favlo/prefix/<model>/<checkpoint>/<hash>.bin`. The checkpoint id is the hex SHA-256 of `manifest.json`, or of `config.json` when the record has no manifest. The file name is the hex SHA-256 of the format, the model id, that digest, the cache tag, and the token ids. The store does not know a key/value layout. Each pipeline packs its own buffers into regions and copies a matching file back.

A prompt that extends the live tokens keeps the device. Any other prompt writes the live sequence, clears the device, and loads the longest stored prefix that pipeline accepts. A match reads the header. Region bytes are read when that prefix is installed. Regions start on a 16 KB page and keep the adapter's capture order on disk. A restore reads the span that holds the named regions in one sequential pass (1 MiB pieces) and hands out `memoryview` slices of that host buffer. The write replaces the destination after the header hash is in place. A region whose stored bytes are a prefix of the new blob is copied forward. The store root (`~/.favlo/prefix`, or one scratch name) stays within 32 GiB across every model and checkpoint under it. Past that, the oldest files are deleted. The file just written stays, and so does every file named in a `pinned` sidecar beside its `.bin` files. A later pin in that directory replaces that name. A request `favlo:prefix_scratch` stores that run under `~/.favlo/prefix-scratch/<name>` instead, and `favlo:prefix_budget` is that forest's byte cap. Format version 2; an older file does not parse and is dropped when the store opens.
